# Web端管理后台 - 项目规则

## 项目概述

本项目是 **WX-APP-OA** 系统的 Web 端管理后台，定位为 **小程序内容中控台 + 系统运维平台**，为运维人员（系统管理员）提供基于浏览器的管理界面，用于：

- 小程序内容编排（工作台配置、功能模块开关、角色菜单可见性）
- 用户管理（用户CRUD、部门管理、批量导入）
- 角色权限管理（自定义角色、权限矩阵配置、角色分配）
- 审批管理（审批模板/流程配置、实例监控）
- 日报管理（提交率统计、批量审核、导出、模板配置）
- 任务与项目管理（项目总览、任务看板、进度统计）
- 资产管理（资产台账、领用审批、盘点、报表）
- 公告管理（发布、阅读统计、范围控制）
- 消息管理（消息模板、手动推送）
- 系统设置（企业信息、安全策略、操作日志、运行监控、数据备份）

**当前阶段**: PRD已确认，准备进入开发阶段

## 技术栈

- **前端框架**: Vue 3 + TypeScript
- **构建工具**: Vite
- **UI组件库**: Element Plus
- **状态管理**: Pinia
- **路由**: Vue Router
- **HTTP客户端**: Axios
- **后端接口**: 对接现有云函数/Node.js后端

## 强制要求

### 1. 上下文加载

- **每次会话开始时，必须先在上下文中加载本 project.md 文件**
- 确保理解项目背景、技术栈和规范后再开始开发

### 2. 意图确认

- **每次接受任务后，仔细分析用户意图**
- 如有不理解或意图模糊时，**必须反问用户确认**，不得擅自猜测
- 确认好意图后再开始执行

### 3. Agent协同

- **在合适的Agent配置中选取Agent调用**
- 如能同时协同多个Agent完成任务，则**协同调用多个Agent**，提升任务效率
- 例如：UI设计 + 前端开发可并行

### 4. Git版本管理

- **每次修改都需要维护git仓库**
- 提交代码修改记录到本地仓库
- 提交信息需清晰描述本次修改内容

### 5. 远程仓库提交限制

- **用户未主动要求，不得擅自提交到远程仓库**
- 所有提交默认只到本地仓库

### 6. 工作目录说明

- 在工作目录维护 README.md 说明该目录下项目内容的情况
- 确保项目文档与README保持同步更新

## 核心原则

> **这是一个纯粹的前端项目**
>
> 在遇到调用后端问题时，需要严格按照后端SDK文档进行调用。
> **如果发现后端SDK有问题，则直接返回问题原因在后端，不要尝试去强行改变前端业务逻辑来适配后端。**
>
> 举例：后端SDK文档中对某个API的定义与后端提供的SDK实际不符合时，需要坚持以文档为主，不得直接使用后端SDK中提供的不符合规范的SDK。
