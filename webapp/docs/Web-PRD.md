## 1. 产品概述

### 1.1 产品背景

智慧办公助手小程序已提供员工端的移动办公能力（审批、日报、任务、项目、资产、公告），但缺乏配套的管理后台。随着小程序用户增长和业务深化，管理员面临以下核心痛点：

- **管理无抓手**：小程序审批流程、日报模板、权限配置等均需后台支撑，缺乏集中管理界面
- **数据不可视**：日报提交率、审批时效、项目进度等管理数据无法在移动端高效查看和统计分析
- **配置无入口**：企业信息、安全策略、功能模块开关、角色菜单可见性等系统配置缺乏统一管理入口
- **运维不透明**：操作日志、运行监控、数据备份等运维工作缺乏可视化工具
- **协作效率低**：批量导入用户、批量审核日报、资产盘点等批量操作在移动端难以完成

### 1.2 产品定位

**OA管理后台**是智慧办公助手系统的 **Web端管理控制台**，定位为 **小程序内容中控台 + 系统运维平台**，为运维人员（系统管理员）提供基于浏览器的管理界面。

核心定位：

- **小程序内容管理中控台**：管理小程序的全部内容配置——工作台布局、功能模块开关、角色菜单可见性、审批模板、日报模板等
- **系统运维平台**：提供用户管理、角色权限、操作审计、运行监控、数据备份等系统级管理能力
- **数据分析中心**：提供日报统计、审批统计、项目进度等数据看板，支撑管理决策
- **批量操作入口**：用户导入导出、日报批量审核、资产批量盘点等桌面端高效操作

### 1.3 目标用户

| ----------------------- | ------------------------------------------------------------ | ------------------------------------------------ | ------------ |
| **系统管理员**    | 企业OA系统运维与管理，负责用户权限、系统配置、数据维护       | 用户管理、角色权限、系统设置、操作日志、运行监控 | 5%           |
| **部门主管/经理** | 中层管理者，需审核日报、审批申请、跟踪项目进度、查看统计数据 | 日报审核、审批处理、项目看板、数据统计、公告发布 | 15%          |
| **高层管理者**    | 企业高管，需全局数据看板、决策分析                           | 仪表盘总览、审批统计、日报统计、项目进度总览     | 2%           |

### 1.4 核心价值主张

| 价值维度               | 具体体现                                                    |
| ---------------------- | ----------------------------------------------------------- |
| **管理效率提升** | 批量用户导入、批量审核日报、一键数据导出，管理效率提升 80%+ |

### 1.5 产品范围

#### 1.5.1 核心功能（P0 — 必须实现）

- **仪表盘**：全局数据看板（审批统计/日报统计/项目进度/系统概览）
- **用户管理**：用户CRUD、部门管理、批量导入导出、账号状态管理
- **角色权限管理**：自定义角色、权限矩阵配置、角色-用户分配、菜单可见性
- **审批管理**：审批类型/模板配置、流程定义、审批实例监控、超时预警
- **日报管理**：日报提交率统计、批量审核、驳回/通过、数据导出、模板配置
- **系统设置**：企业信息配置、安全策略（密码/登录/IP白名单）、操作日志、数据备份

#### 1.5.2 重要功能（P1 — 建议实现）

- **小程序内容编排**：工作台配置（模块排序/显示隐藏）、功能模块全局开关、角色菜单可见性
- **任务与项目管理**：项目总览、任务看板（拖拽）、项目成员管理、进度统计
- **资产管理**：资产台账CRUD、领用/归还审批、资产盘点、资产报表
- **公告管理**：公告发布（企业/部门）、阅读统计、置顶/下线、范围控制
- **消息管理**：消息模板配置、手动消息推送、推送记录查看
- **个人中心**：个人信息编辑、修改密码、消息通知偏好设置

#### 1.5.3 增值功能（P2 — 可选实现）

- **高级审批**：并行审批分支、会签/加签/转签、条件审批规则
- **数据报表**：甘特图、工时统计、效率分析、自定义报表导出
- **考勤管理**：签到记录查看、请假/加班审批统计
- **文档管理**：企业文件管理、在线预览、版本管理
- **运行监控**：服务器资源监控、API调用统计、错误告警
- **企业微信/钉钉集成**：消息同步、通讯录同步

## 2. 功能需求

### 2.1 用户认证与登录模块

#### 2.1.1 功能描述

提供Web端管理员登录认证体系，支持账号密码登录，与企业统一认证体系打通，基于JWT Token维持登录态。

#### 2.1.2 功能列表

| 功能编号 | 功能名称     | 功能描述                                                             | 优先级 | 用户角色   |
| -------- | ------------ | -------------------------------------------------------------------- | ------ | ---------- |
| AUTH-01  | 管理员登录   | 输入账号/密码登录Web管理后台，验证通过后下发JWT Token                | P0     | 全部管理员 |
| AUTH-02  | Token管理    | Token持久化到localStorage，每次请求自动携带，支持自动续期            | P0     | 全部管理员 |
| AUTH-03  | 退出登录     | 清除本地Token并跳转登录页，同时使服务端Token失效                     | P0     | 全部管理员 |
| AUTH-04  | 登录状态保持 | 关闭浏览器后Token有效期内再次打开保持登录态                          | P1     | 全部管理员 |
| AUTH-05  | 登录拦截     | 未登录用户访问任何页面自动跳转登录页，登录用户访问登录页自动跳转首页 | P0     | 系统       |
| AUTH-06  | 验证码登录   | 支持图形验证码或短信验证码登录，防止暴力破解                         | P1     | 全部管理员 |
| AUTH-07  | 登录安全策略 | 支持登录失败次数限制、异常IP检测、登录通知                           | P2     | 系统       |

#### 2.1.3 登录流程

```
[用户访问Web管理后台]
    ↓
[判断Token是否存在且有效]
    ↓ 无有效Token          ↓ 有有效Token
[登录页]              [自动跳转仪表盘首页]
    ↓
[输入账号/密码]
    ↓
[POST /api/auth/admin/login]
    ↓ 失败                    ↓ 成功
[显示错误提示]          [下发JWT Token]
    ↓                      ↓
[可重试]              [缓存Token + 用户信息]
                          ↓
                    [跳转仪表盘首页]
```

## 3. 非功能需求

### 3.1 性能需求

| 指标             | 目标值   | 说明                         |
| ---------------- | -------- | ---------------------------- |
| 页面首次加载     | ≤ 3秒   | 从打开到首页渲染完成         |
| 页面切换         | ≤ 1秒   | 路由切换/页面跳转响应时间    |
| API响应时间(P50) | ≤ 300ms | 90%的API请求在300ms内返回    |
| 列表分页加载     | ≤ 1.5秒 | 每页20条数据加载时间         |
| 数据导出         | ≤ 5秒   | 1万条以内数据导出为Excel     |
| 批量导入         | ≤ 10秒  | 1000条用户数据导入时间       |
| 并发用户数       | 支持200  | 同时在线管理员用户数         |
| 首包体积         | ≤ 500KB | 首次加载JavaScript/CSS包大小 |

### 3.2 安全需求

| 需求编号 | 安全需求    | 说明                                                | 优先级 |
| -------- | ----------- | --------------------------------------------------- | ------ |
| SEC-01   | HTTPS加密   | 所有API通信必须使用TLS 1.2+加密                     | P0     |
| SEC-02   | Token认证   | 使用JWT Bearer Token，设置合理过期时间（默认8小时） | P0     |
| SEC-03   | XSS防护     | 所有用户输入输出进行XSS转义处理                     | P0     |
| SEC-04   | CSRF防护    | 关键操作（删除/修改配置）校验Referer或Token         | P0     |
| SEC-05   | SQL注入防护 | 使用参数化查询，禁止拼接SQL语句                     | P0     |
| SEC-06   | 权限校验    | 前端路由守卫 + 后端接口双重校验，防止越权操作       | P0     |
| SEC-07   | 操作审计    | 所有敏感操作记录日志（操作人/IP/时间/详情）         | P0     |
| SEC-08   | 密码安全    | 密码加密存储（bcrypt），传输过程加密                | P0     |
| SEC-09   | 会话管理    | 支持Token主动失效、同一账号限制同时登录设备数       | P1     |
| SEC-10   | 数据脱敏    | 手机号、邮箱等敏感信息列表展示时脱敏                | P0     |
