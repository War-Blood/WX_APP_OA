## 通用规范

### 统一响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 认证方式

除登录和健康检查外，所有接口均需在请求头中携带：

```
Authorization: Bearer <token>
```

### HTTP 方法

| 方法 | 用途 |
|------|------|
| `GET` | 查询资源 |
| `POST` | 创建资源、复杂列表查询 |
| `PUT` | 更新资源 |
| `DELETE` | 删除资源 |

### 全局错误码

| code | HTTP Status | 含义 | 说明 |
|------|-------------|------|------|
| 0 | 200 | 成功 | 正常返回 |
| 401 | 401 | 未授权 / Token 过期 | 需重新登录 |
| 403 | 403 | 无权限 | 角色无操作权限 |
| 429 | 429 | 请求过于频繁 | 触发限流 |
| 1001 | 400 | 参数校验失败 | 请求参数不符合要求 |
| 1002 | 404 | 资源不存在 | 请求的资源未找到 |
| 2001 | 200 | 业务逻辑错误 | 如重复提交、状态冲突 |
| 2002 | 200 | 审批已处理 | 审批单已被操作过 |
| 2003 | 200 | 日报已审核 | 日报已被审核过 |
| 500 | 500 | 服务器内部错误 | 未知异常，请联系管理员 |

## M2 基础架构

### 健康检查

> 用于服务健康状态监控，不依赖 JWT 认证。

#### `GET /api/health`

**认证方式：** 无需认证

**请求参数：** 无

**响应数据：**

| 字段 | 类型 | 说明 |
|------|------|------|
| status | string | 服务状态：`ok` / `degraded` |
| timestamp | string | 当前服务器时间（ISO 8601） |
| uptime | number | 服务运行时长（秒） |
| version | string | API 版本号 |
| checks | object | 各依赖项健康检查详情 |
| checks.database | object | MySQL 连接状态 |
| checks.database.status | string | `ok` / `error` |
| checks.database.responseTime | string | 响应耗时，如 `5ms` |
| checks.redis | object | Redis 连接状态 |
| checks.redis.status | string | `ok` / `error` |
| checks.redis.responseTime | string | 响应耗时，如 `2ms` |

**请求示例：**

```bash
curl http://111.229.107.123:3000/api/health
```

**响应示例（正常）：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "ok",
    "timestamp": "2026-05-29T10:00:00.000Z",
    "uptime": 12345,
    "version": "1.0.0",
    "checks": {
      "database": {
        "status": "ok",
        "responseTime": "5ms"
      },
      "redis": {
        "status": "ok",
        "responseTime": "2ms"
      }
    }
  }
}
```

**响应示例（降级）：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "degraded",
    "timestamp": "2026-05-29T10:00:00.000Z",
    "uptime": 12345,
    "version": "1.0.0",
    "checks": {
      "database": {
        "status": "ok",
        "responseTime": "5ms"
      },
      "redis": {
        "status": "error",
        "message": "connect ECONNREFUSED 127.0.0.1:6379"
      }
    }
  }
}
```

**错误码：**

| code | 场景 |
|------|------|
| 0 | 成功返回（即使有依赖降级也返回 0） |

## 3. 认证模块 (Auth)

### 3.1 微信登录

> M3 阶段实现。通过微信 code 换取登录态。

#### `POST /api/auth/login`

**认证方式：** 无需认证

**请求参数：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| code | string | 是 | 微信 `wx.login()` 返回的临时 code |

**请求示例：**

```json
{
  "code": "0a3xxx..."
}
```

**响应数据：**

| 字段 | 类型 | 说明 |
|------|------|------|
| token | string | JWT Token，后续请求携带 |
| userInfo | object | 用户基本信息 |
| userInfo.openid | string | 微信 OpenID |
| userInfo.nickName | string | 用户昵称 |
| userInfo.avatarUrl | string | 头像 URL |
| userInfo.role | string | 角色：`employee` / `admin` / `superadmin` |
| userInfo.department | string | 所属部门 |
| userInfo.userId | string | 系统用户 ID |

**响应示例：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "userInfo": {
      "openid": "oXXXX...",
      "nickName": "张三",
      "avatarUrl": "https://...",
      "role": "employee",
      "department": "技术部",
      "userId": "U10001"
    }
  }
}
```

**错误码：**

| code | 场景 |
|------|------|
| 0 | 登录成功 |
| 1001 | code 参数缺失 |
| 2001 | 微信接口调用失败（code 无效） |
