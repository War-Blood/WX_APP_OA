## 简介
本文件面向"智慧办公助手 OA 系统"的生产部署，覆盖服务器基础设施、后端 API 服务（PM2 进程管理、Nginx 反向代理、SSL 证书）、前后端（小程序与 Web 后台）静态资源与缓存策略、数据库与缓存高可用方案（MySQL 主从、Redis 集群）、环境变量、日志与监控告警、备份与恢复等完整配置指南。**新增** Docker 容器化部署和 RBAC 权限系统的部署说明，确保可落地、可验证。

## 项目结构
系统采用前后端分离架构：
- 后端：基于 Node.js + Express 的 RESTful API 服务，负责认证、审批、报表、消息、统计等功能。
- 前端：小程序与 Web 后台分别独立构建，通过反向代理统一接入后端 API。
- 数据层：MySQL（双库：wx_app_oa 新库 + daily_report 旧库兼容），Redis 缓存。
- **新增** 容器化：Docker Compose 编排 MySQL、Redis、后端 API 和 Nginx。

### Docker 容器化部署（新增）
- **容器镜像构建**
  - 使用 Node.js 18 Alpine 基础镜像，安装生产依赖，复制源码与 PM2 配置。

  - 后端 API：依赖 MySQL 和 Redis 健康状态，配置环境变量。
  - Nginx：映射 80/443 端口，挂载配置与静态资源。
- **健康检查**
  - MySQL：mysqladmin ping 检测。
  - Redis：redis-cli ping 检测。
  - API：HTTP GET /api/health 检测。
  - Nginx：依赖后端健康状态。

### RBAC 权限系统部署（新增）
- **数据库迁移**
  - 创建 roles、permissions、role_permissions 三张核心表。
  - 预置系统角色：superadmin、admin、employee。
  - 预置权限：用户管理、角色管理、部门管理、审批管理、日报管理、公告管理、项目管理、任务管理、资产管理、系统设置、合规管理等。
  - 建立角色-权限关联，设置不同角色的默认权限。
  - 为 users 表添加索引优化查询性能。
- **权限控制实现**
  - JWT 认证中间件：验证 Token，检查用户状态与角色一致性。
  - 角色鉴权：requireRole 中间件，验证用户角色。
  - 权限鉴权：requirePermission 中间件，基于角色-权限表动态加载权限。
  - 权限缓存：Map 缓存角色权限集合，5 分钟 TTL，权限变更主动清除。
  - 管理接口：角色 CRUD、权限列表、设置角色权限。
- **权限验证流程**

## 性能考虑
- 连接池与事务
  - 合理设置 poolMin/poolMax，避免峰值拥塞；对批量写入使用事务减少锁竞争。
- 缓存策略
  - 热点数据放入 Redis，设置合适过期策略；对读多写少场景使用多级缓存。
- 网络与中间件
  - Nginx 层开启 gzip/缓存，Helmet/CORS/限流降低后端压力。
- 前端优化
  - 静态资源 CDN、按需加载、图片压缩与懒加载，减少首屏阻塞。
- **新增** RBAC 性能优化
  - 权限缓存：5 分钟 TTL，权限变更主动清除，减少数据库查询压力。
  - 索引优化：users 表添加 department_id、user_name 索引。

## 故障排查指南
- 启动失败
  - 检查必需环境变量是否齐全；查看日志文件定位错误。
- 数据库无法连接
  - 使用 ping 方法验证连通性；核对主机、端口、账号、密码与网络策略。
- Redis 连接异常
  - 查看重连日志与错误事件；确认密码、DB 选择与网络连通。
- 429 限流
  - 检查全局限流与登录端点限流策略，必要时临时放宽或调整白名单。
- 优雅退出
  - 观察 SIGTERM/SIGINT 处理流程，确保 Redis 与 HTTP 服务有序关闭。
- **新增** RBAC 权限问题
  - 检查角色-权限关联是否正确；清理权限缓存后重试；验证用户角色状态。
- **新增** Docker 容器问题
  - 使用 docker compose ps 查看服务状态；检查容器日志；验证数据卷挂载。
