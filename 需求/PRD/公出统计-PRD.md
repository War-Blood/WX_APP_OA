## 一、公出日志填写

### 1.1 日志类型

| 类型 | 说明 | 提交后状态 |
|------|------|-----------|
| 公出日志 | 当日公出填报 | 直接通过 |
| 补公出日志 | 补录历史日期 | 待审核 |

### 1.2 工作类型

| 可选值 | 含义 |
|--------|------|
| 工作（陆） | 陆地现场作业 |
| 工作（海） | 海上作业 |
| 待工 | 等待安排 |
| 在途 | 差旅途中 |
| 请假 | 请假（特殊处理） |

### 1.3 字段一览

| # | 字段 | 类型 | 必填 | 请假时 | 说明 |
|:--:|------|------|:--:|:--:|------|
| 1 | 填写日期 | date | ✅ | ✅ | 仅昨日/今日可选 |
| 2 | 工作类型 | select | ❌ | — | 默认"工作（陆）" |
| 3 | 项目名称 | input | ✅* | 跳过 | 请假自动填"请假" |
| 4 | 项目区域 | 省市区picker | ✅* | 跳过 | 三级联动 |
| 5 | 初始出差时间 | date | ✅* | 跳过 | |
| 6 | 工作内容 | textarea | ✅* | 跳过 | |
| 7 | 需求数量 | number | ✅* | 跳过 | |
| 8 | 完成数量 | number | ✅* | 跳过 | |
| 9 | 作业人员 | 多选 | ✅ | ✅ | 花名册选人 |
| 10 | 机型 | input | ❌ | ❌ | |
| 11 | 相关方 | input | ❌ | ❌ | |
| 12 | 备注 | textarea | ❌ | ❌ | |
| 13 | 补录日期 | date | — | — | 仅补公出必填 |
| 14 | 补录原因 | textarea | — | — | 仅补公出必填 |

> ✅*=非请假时必填，请假时跳过。✅=始终必填。❌=可选。—=仅特定类型。

### 1.4 请假特殊逻辑

选"请假"后：跳过项目名称/区域/出差时间/工作内容/需求/完成数量的校验；日期不限范围；提交后直接通过。

## 二、公出统计

### 2.1 入口

小程序「我的」→「公出统计」。管理员 5 个 Tab，普通员工仅「个人统计」。

### 2.2 个人统计

| 指标 | 内容 |
|------|------|
| 累计条数 | 全部历史 approved 日志数（含代填） |
| 当月条数 | 本月 approved 日志数 |
| 缺失天数 | 入场日期至今应填未填天数 |
| 延迟条数 | 标识为延迟的日志数 |
| 月度工作占比 | 本月各工作类型天数柱状图 |
| 同组日志 | 同项目人员最近 7 天日志 |

### 2.3 全员当日

默认显示昨日。人员包含当日有日志的所有人+在职未提交的人。分组：未提交 → 补公出 → 请假 → 已提交。点击卡片可跳详情。

### 2.4 日历热力图

按月查看每日提交人次，颜色深浅表示数量。

### 2.5 项目进展

按月查看各项目进度。完成/需求取该月最新一条日志的值。进度低的排前面。点击项目查看日志明细。

### 2.6 人员分布

**工作类型分布表**：每人每月各工作类型天数。点击人员查看日志明细。

**区域分布（昨日）**：左列省份 + 右列该省人员名单。仅看昨日数据。点击省份查看人员详情。

---

## 三、核心规则

1. **人员三路径**：统计某人是否参与某日工作，通过①自己提交 ②被代填 ③workers名单匹配 三条路径判定，同人同日只计一次
2. **统计范围**：有公出日志数据的人都会显示，不受花名册在职/离职限制
3. **未提交判定**：仅对在职外场人员检查昨日是否提交，离职人员不参与
4. **区域分布**：仅看昨日，省份按 `area` 字段取第一段，同一人多省分别计数
5. **管理员排除**：系统管理员（admin/superadmin）不参与数据统计
