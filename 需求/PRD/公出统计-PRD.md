## 一、产品概述

### 1.1 功能定位

公出统计为 OA 系统的数据看板模块，面向**员工**和**管理员**两种角色提供差异化的统计视图：

| 角色 | 端 | 视角 | 核心目标 |
|------|----|------|---------|
| 员工 | 小程序 | 个人 | 了解自己的出勤与工作占比，发现缺失日期 |
| 管理员 | Web 后台 + 小程序 | 全局 | 监控全员出勤情况、项目进展、区域分布、人员工作状态 |

> ⚠️ **管理端双端覆盖**: 管理员在小程序上同样可查看全部管理统计视图（日历热力图、项目进展、人员分布、昨日一览、区域地图），Web 后台提供更完整的图表交互和大屏展示能力。

### 1.2 数据来源

全部统计数据来自 `daily_reports` 表，**仅计入 `status = 'approved'`（审核通过）的公出日志**（`report_type != 'office'`）。

关键字段：
- `report_date` — 日报日期
- `project` — 项目名称
- `area` — 项目区域（格式：`省-市-区`，如 `广东省-广州市-天河区`）
- `today_work_type` — 当日工作类型（工作（陆）/ 工作（海）/ 待工 / 在途 / 请假 / 调休）
- `workers` — 作业人员（逗号分隔文本）
- `required_qty` / `completed_qty` — 需求/完成数量
- `user_id` — 提交人

## 二、员工端（小程序）

> 页面路径: `pages/profile/stats`  
> 当前状态: **已基本实现**，以下为功能描述与验收标准

### 2.1 个人统计四格卡片

**布局**: 一行四列等宽卡片

| 卡片 | 字段 | 颜色 |
|------|------|------|
| 累计条数 | `totalCount` — 历史审核通过的公出日志总数（含代填+补录） | 蓝色 `#2B6DE8` |
| 当月条数 | `monthCount` — 当前月份审核通过的公出日志数 | 绿色 `#22C55E` |
| 缺失天数 | `missingDays` — 从入场日至昨日期间未提交的天数 | 有缺失红色，无缺失绿色 |
| 延迟条数 | `delayedCount` — 审核通过但标记为延迟的日志数 | 有延迟黄色，无延迟绿色 |

**数据接口**: `POST /api/report/stats` `{ scope: 'user', userId }`

**验收标准**:
- [ ] 四格卡片数值正确，仅统计 `status='approved'` 的记录
- [ ] 缺失天数 = 入场日→昨日之间的工作日中无审核通过记录的天数
- [ ] 缺失日期列表折叠在下方，最多展示最近 30 条
- [ ] 下拉刷新后数据更新

### 2.2 月度工作占比

**布局**: 横向柱状图列表

每种工作类型一行，包含：
- 工作类型名称（右对齐，固定宽度 120rpx）
- 横向进度条（蓝色渐变，宽度对应百分比）
- 百分比数字
- 天数

**工作类型**: `工作（陆）`、`工作（海）`、`待工`、`在途`、`请假`、`调休`

**数据接口**: `POST /api/report/monthly-summary` `{ userId, month }`

**验收标准**:
- [ ] 仅统计审核通过的记录
- [ ] 百分比 = 该类型天数 / 总提交天数 × 100%，分母为 0 时显示 0%
- [ ] 柱状图有 0.5s 过渡动画
- [ ] 同组日志列表可点击跳转日报详情

### 3.1 月度提交日历热力图

**需求描述**: 以日历热力图展示当前月份每天提交公出日志的人次数，**每个日期格内直接标注具体数值**。

**视觉设计**:
```
┌───────────────────────────────────────────────┐
│  2026年6月 公出日志提交日历                      │
│       一    二    三    四    五    六    日     │
│      ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐     │
│      │  │ │  │ │ 3│ │ 5│ │ 7│ │ 2│ │  │     │
│      └──┘ └──┘ └──┘ └──┘ └──┘ └──┘ └──┘     │
│  ← 浅蓝底色  中蓝底色  深蓝底色（数字越大越深） →  │
│  □ 0人  □ 1-3人  □ 4-6人  □ 7-10人  □ 10+人   │
└───────────────────────────────────────────────┘
```
- 每个格子内**必须显示具体数字**，颜色深浅为辅助视觉
- 0 人显示"0"（灰色底），>0 的数字清晰可读
- 颜色分 5 档：灰(0) / 浅蓝(1-3) / 中蓝(4-6) / 深蓝(7-10) / 最深蓝(10+)

**实现方案**: 使用 ECharts Calendar Heatmap，开启 `label.show: true` 在每个日期格显示数值

**数据接口**: `POST /api/stats/daily-counts`（新增）
- 请求: `{ month: "2026-06" }`
- 响应: `{ data: [{ date: "2026-06-01", count: 5 }, ...] }` — 每天审核通过的公出日志人次

**交互**: 
- 日期格直接显示数字，颜色深浅辅助判断
- 点击某一天可下钻查看当日提交详情

**验收标准**:
- [ ] 每个日期格内直接标注具体人次数字
- [ ] 颜色深浅 5 档与当日人次正相关
- [ ] 支持月份切换（上个月/下个月）
- [ ] 仅统计 `status='approved'` 且 `report_type != 'office'` 的记录

**小程序适配**: 使用 `<view>` 网格布局 7×N 日期格（非 canvas），每格显示日期号 + 人次数字，rpx 自动适配。颜色分 3 档（灰/中蓝/深蓝），点击日期弹出当日提交人员列表。

### 3.2 项目进展看板

**需求描述**: 当前月份有日志提交的项目，按进度排序展示。

**布局**: 表格 + 进度条

| 列 | 来源 | 说明 |
|----|------|------|
| 项目名称 | `project` | 去重聚合 |
| 所在区域 | `area`（取省份） | 多个区域时显示主要区域 |
| 作业人数 | `workers` 去重统计 | 本月该项目涉及的作业人员数 |
| 累计完成量 | `MAX(completed_qty)` | 取本月该项目所有日志中完成量的**最高值** |
| 总需求量 | `MAX(required_qty)` | 取本月该项目所有日志中需求量的**最高值** |
| 进度 | `完成量/需求量 × 100%` | 进度条 + 百分比 |
| 日均人次 | `总人次 / 有日志天数` | — |

> 💡 **为什么取最高值而非求和**: 同一个项目的每日日志通常报的是**累计进度**（如 Day3 完成 80/200，Day4 完成 120/200），求和会导致数据重复计算。取当月最高值即为最新进度。

**排序**: 默认按进度升序（进度低的排前面，引起关注）

**数据接口**: `POST /api/stats/project-progress`（新增）
- 请求: `{ month: "2026-06" }`
- 响应: `{ projects: [{ project, area, workerCount, completedQty, requiredQty, progress, dailyAvg }] }`

**验收标准**:
- [ ] 仅统计审核通过的公出日志
- [ ] 进度 = MAX(completed_qty) / MAX(required_qty) × 100%（取当月最高值）
- [ ] 需求量/完成量为整数
- [ ] 需求量为 0 时进度显示"无数据"
- [ ] 进度低于 50% 的项目高亮警告色

**小程序适配**: 改为纵向卡片列表，每张卡片展示项目名 + 区域 + 进度条，替代横向表格。进度条使用 `view` 实现（同 report-edit 的 `.ratio-bar` 模式）。

### 3.3 人员工作状态分布

**需求描述**: 展示每个在职人员当前月份不同工作类型的分布。

**布局方案**: 表格 + 迷你色条（方案 B）
- 每行一个人员，列：姓名 | 工号 | 工作(陆) | 工作(海) | 待工 | 在途 | 请假 | 调休 | 总天数
- 每个数字格内用**浅色背景条**表示数值大小（颜色深 = 天数多）
- 支持按总天数降序/升序排序

> ⚠️ **不采用堆叠柱状图**: 外场人员可达 50+ 人，堆叠柱状图 X 轴过密看不清，表格方案无论人数多少都可完整展示。

**视觉设计**:
```
  ┌────────┬──────┬────┬────┬────┬────┬────┬────┬──────┐
  │ 姓名   │ 工号  │ 陆 │ 海 │ 待 │ 途 │ 假 │ 休 │ 总计  │
  ├────────┼──────┼────┼────┼────┼────┼────┼────┼──────┤
  │ 张三   │ BL01 │ █8 │ █4 │  1 │    │  1 │    │  14  │
  │ 李四   │ BL02 │ ██12│  2 │    │ █8 │    │    │  22  │
  │ ...    │      │    │    │    │    │    │    │      │
  └────────┴──────┴────┴────┴────┴────┴────┴────┴──────┘
   ← 背景色深浅 = 天数多少（0无背景，1-2浅，3-5中，5+深）→
```

**数据接口**: `POST /api/stats/worker-work-types`（新增）
- 请求: `{ month: "2026-06" }`
- 响应: `{ workers: [{ userName, workerCode, workTypes: { "工作（陆）": 3, ... }, total }] }`

**验收标准**:
- [ ] 仅统计审核通过的在职人员的公出日志
- [ ] 表格每格数字 + 背景色条双重编码
- [ ] 支持按任意列排序
- [ ] 总计列粗体突出

**小程序适配**: 表格横向字段较多（9 列），使用 `scroll-view` 横向滚动表格。首列（姓名）固定左侧不滚动。每个数字格底色与 Web 端一致的深浅编码。

### 4.3 接口规范

所有接口遵循项目统一规范：
- `POST` + JSON body
