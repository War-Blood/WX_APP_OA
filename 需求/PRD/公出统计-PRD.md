> 版本: v1.0 | 日期: 2026-06-22 | 状态: 设计中
>
> 关联模块: 日报模块 `daily_reports`、统计模块 `core/services/stats.service.js`

## 一、产品概述

### 1.1 功能定位

公出统计为 OA 系统的数据看板模块，面向**员工**和**管理员**两种角色提供差异化的统计视图：

| 角色 | 端 | 视角 | 核心目标 |
|------|----|------|---------|
| 员工 | 小程序 | 个人 | 了解自己的出勤与工作占比，发现缺失日期 |
| 管理员 | Web 后台 + 小程序 | 全局 | 监控全员出勤情况、项目进展、区域分布、人员工作状态 |

> ⚠️ **管理端双端覆盖**: 管理员在小程序上同样可查看全部管理统计视图（日历热力图、项目进展、人员分布、昨日一览、区域地图），Web 后台提供更完整的图表交互和大屏展示能力。

### 1.2 数据来源

全部统计数据来自 `daily_reports` 表，**仅计入 `status = 'approved'`（审核通过）的公出日志**（`report_type != 'office'`）。

关键字段：
- `report_date` — 日报日期
- `project` — 项目名称
- `area` — 项目区域（格式：`省-市-区`，如 `广东省-广州市-天河区`）
- `today_work_type` — 当日工作类型（工作（陆）/ 工作（海）/ 待工 / 在途 / 请假 / 调休）
- `workers` — 作业人员（逗号分隔文本）
- `required_qty` / `completed_qty` — 需求/完成数量
- `user_id` — 提交人

## 二、员工端（小程序）

> 页面路径: `pages/profile/stats`  
> 当前状态: **已基本实现**，以下为功能描述与验收标准

### 2.1 个人统计四格卡片

**布局**: 一行四列等宽卡片

| 卡片 | 字段 | 颜色 |
|------|------|------|
| 累计条数 | `totalCount` — 历史审核通过的公出日志总数（含代填+补录） | 蓝色 `#2B6DE8` |
| 当月条数 | `monthCount` — 当前月份审核通过的公出日志数 | 绿色 `#22C55E` |
| 缺失天数 | `missingDays` — 从入场日至昨日期间未提交的天数 | 有缺失红色，无缺失绿色 |
| 延迟条数 | `delayedCount` — 审核通过但标记为延迟的日志数 | 有延迟黄色，无延迟绿色 |

**数据接口**: `POST /api/report/stats` `{ scope: 'user', userId }`

**验收标准**:
- [ ] 四格卡片数值正确，仅统计 `status='approved'` 的记录
- [ ] 缺失天数 = 入场日→昨日之间的工作日中无审核通过记录的天数
- [ ] 缺失日期列表折叠在下方，最多展示最近 30 条
- [ ] 下拉刷新后数据更新

### 2.2 月度工作占比

**布局**: 横向柱状图列表

每种工作类型一行，包含：
- 工作类型名称（右对齐，固定宽度 120rpx）
- 横向进度条（蓝色渐变，宽度对应百分比）
- 百分比数字
- 天数

**工作类型**: `工作（陆）`、`工作（海）`、`待工`、`在途`、`请假`、`调休`

**数据接口**: `POST /api/report/monthly-summary` `{ userId, month }`

**验收标准**:
- [ ] 仅统计审核通过的记录
- [ ] 百分比 = 该类型天数 / 总提交天数 × 100%，分母为 0 时显示 0%
- [ ] 柱状图有 0.5s 过渡动画
- [ ] 同组日志列表可点击跳转日报详情

## 三、管理端（Web 后台 + 小程序管理视图）

> 页面路径:  
> - Web: `webapp/src/views/report/stats.vue`（需大幅改造）  
> - 小程序: `miniapp/src/pages/profile/stats.vue`（扩展管理员 Tab）  
> 当前状态: **待实现**（小程序仅实现了"全员当日"一个管理员 Tab，需扩展）  
> 技术栈: Web — Vue 3 + TypeScript + ECharts 5.5；小程序 — uni-app + canvas/ECharts 小程序版

### 双端适配原则

| 功能 | Web 后台 | 小程序管理端 |
|------|---------|------------|
| 日历热力图 | ECharts Calendar Heatmap | canvas 绘制简化版日历热力图 |
| 项目进展看板 | 表格 + 进度条 | 卡片列表 + 进度条 |
| 人员工作状态分布 | 堆叠柱状图（ECharts） | 表格 + 迷你色条 |
| 昨日工作一览 | 表格，支持日期切换 | 同 Web，适配移动端横向滑动表格 |
| 中国地图 | ECharts China Map，点击省份弹窗 | 省份列表卡片（地图在小程序上受包体积限制，降级为省份排名列表，点击展开详情） |

> 小程序上 ECharts 地图需要额外引入 echarts-for-weixin 组件（约 800KB），会显著增加小程序包体积。建议小程序端**降级为省份排行榜 + 点击展开详情**，保持功能完整性的同时避免超过 2MB 包体积限制。

### 小程序管理端入口

管理员（`role = 'admin' | 'superadmin'`）进入公出统计页时，底部 Tab 栏额外显示：
```
[ 个人统计 ]  [ 全员当日 ]  [ 📅 日历 ]  [ 📊 看板 ]
```

- **个人统计** — 同员工视图（2.1 + 2.2）
- **全员当日** — 已有的当日全员状态视图
- **日历** — 月度热力图（3.1 简化版）
- **看板** — 项目进展 + 人员分布 + 区域分布整合卡片列表（3.2 ~ 3.5 整合）

下面各节以 Web 端为主描述功能细节，小程序端适配差异在各节末尾标注。

### 3.1 月度提交日历热力图

**需求描述**: 以日历热力图展示当前月份每天提交公出日志的人次数。

**视觉设计**:
```
┌─────────────────────────────────────────────┐
│  2026年6月 公出日志提交日历                    │
│  一  二  三  四  五  六  日                    │
│  ○   ○   ○   ○   ○   ○   ○                  │
│  ○   ●   ●   ●   ●   ○   ○   ← 颜色深浅=人次  │
│  ●   ●   ●   ●   ●   ○   ○                  │
│  ...                                          │
│  □ 0  □ 1-3  □ 4-6  □ 7-10  □ 10+  (图例)   │
└─────────────────────────────────────────────┘
```

**实现方案**: 使用 ECharts Calendar Heatmap

**数据接口**: `POST /api/stats/daily-counts`（新增）
- 请求: `{ month: "2026-06" }`
- 响应: `{ data: [{ date: "2026-06-01", count: 5 }, ...] }` — 每天审核通过的公出日志人次

**交互**: 
- 鼠标悬停显示日期 + 具体人次
- 点击某一天可下钻查看当日提交详情

**验收标准**:
- [ ] 正确渲染当月日历（含跨月补齐的空白格）
- [ ] 每个日期格颜色深浅与当日人次正相关
- [ ] 支持月份切换（上个月/下个月）
- [ ] 仅统计 `status='approved'` 且 `report_type != 'office'` 的记录

**小程序适配**: 使用 `<canvas>` 绘制 7×N 网格日历，rpx 适配宽度，颜色用 3 档渐变（浅蓝/中蓝/深蓝），点击日期弹出当日提交人员列表。

### 3.2 项目进展看板

**需求描述**: 当前月份有日志提交的项目，按进度排序展示。

**布局**: 表格 + 进度条

| 列 | 来源 | 说明 |
|----|------|------|
| 项目名称 | `project` | 去重聚合 |
| 所在区域 | `area`（取省份） | 多个区域时显示主要区域 |
| 作业人数 | `workers` 去重统计 | 本月该项目涉及的作业人员数 |
| 累计完成量 | `SUM(completed_qty)` | 本月所有日志的 completed_qty 合计 |
| 总需求量 | `SUM(required_qty)` | 本月所有日志的 required_qty 合计 |
| 进度 | `完成量/需求量 × 100%` | 进度条 + 百分比 |
| 日均人次 | `总人次 / 有日志天数` | — |

**排序**: 默认按进度升序（进度低的排前面，引起关注）

**数据接口**: `POST /api/stats/project-progress`（新增）
- 请求: `{ month: "2026-06" }`
- 响应: `{ projects: [{ project, area, workerCount, completedQty, requiredQty, progress, dailyAvg }] }`

**验收标准**:
- [ ] 仅统计审核通过的公出日志
- [ ] 进度 = SUM(completed_qty) / SUM(required_qty) × 100%
- [ ] 需求量/完成量为整数
- [ ] 进度低于 50% 的项目高亮警告色

**小程序适配**: 改为纵向卡片列表，每张卡片展示项目名 + 区域 + 进度条，替代横向表格。进度条使用 `view` 实现（同 report-edit 的 `.ratio-bar` 模式）。

### 3.3 人员工作状态分布

**需求描述**: 展示每个在职人员当前月份不同工作类型的分布。

**布局方案 A（推荐）**: 堆叠柱状图
- X 轴：人员姓名
- Y 轴：天数
- 堆叠段：工作（陆）/ 工作（海）/ 待工 / 在途 / 请假 / 调休
- 每个柱子上方标注总天数

**布局方案 B**: 表格 + 迷你柱状图
- 每行一个人员，列：姓名 → 陆/海/待/途/假/休 各列数值 → 总天数

**数据接口**: `POST /api/stats/worker-work-types`（新增）
- 请求: `{ month: "2026-06" }`
- 响应: `{ workers: [{ userName, workTypes: { "工作（陆）": 3, ... }, total }] }`

**验收标准**:
- [ ] 仅统计审核通过的公出日志
- [ ] 仅统计在职人员（`worker_status='active'`）
- [ ] 支持按总天数排序
- [ ] 图例可点击切换显示/隐藏某类型

**小程序适配**: 改为人员卡片列表，每张卡片展示姓名 + 6 种工作类型横向迷你色条（同月度占比的 `.ratio-bar`），点击展开详情。

### 3.4 昨日工作一览

**需求描述**: 表格展示所有在职人员昨日的工作状态和所在项目。

**表格列**:

| 列 | 说明 |
|----|------|
| 姓名 | `nickname` / `user_name` |
| 工号 | `worker_code` |
| 工作状态 | 已提交 / 补公出 / 请假 / 调休 / 已代填 / ✗ 未提交 |
| 工作类型 | `today_work_type`（缺失时为空） |
| 项目名称 | `project` |
| 所在区域 | `area`（取省份） |
| 提交时间 | `submitted_at` |

**排序**: 未提交排最前，其余按提交时间倒序

**数据接口**: `POST /api/report/daily-status`（现有接口，`{ date: "2026-06-21" }`，已实现）
- 可复用，仅需确保前端展示完整字段

**验收标准**:
- [ ] 默认显示昨日（`new Date() - 1 day`）
- [ ] 支持日期切换查看任意历史日期
- [ ] 未提交人员红色高亮
- [ ] 数据仅含审核通过的公出日志

**小程序适配**: 已存在（当前小程序的"全员当日" Tab 即为此功能），需补充日期切换器和完整字段展示（项目、区域、工作类型）。

### 3.5 中国地图区域分布

**需求描述**: 以中国地图展示人员按省份的分布，数据来源为 `area` 字段的省份部分。

**实现方案**: ECharts China Map（需加载中国 GeoJSON 或使用 `echarts/map/js/china.js`）

**视觉设计**:
```
┌──────────────────────────────────────────┐
│          .───────.                        │
│        ,'         `.    新疆: 3人         │
│       /   新疆  3   \                     │
│      ;              :    ┌──── 图例 ────┐ │
│      :   西藏  1     ;   │ ■ 0人        │ │
│       \            /     │ ■ 1-3人      │ │
│        `.   四川 12 ,'    │ ■ 4-8人      │ │
│          `.──┬──,'       │ ■ 9-15人     │ │
│  ┌──────────┼──────────┐ │ ■ 15人+      │ │
│  │  广东 12 │  福建 5   │ └──────────────┘ │
│  └──────────┴──────────┘                  │
└──────────────────────────────────────────┘
```

**数据接口**: `POST /api/stats/area-distribution`（新增）
- 请求: `{ month?: "2026-06" }`（可选月份筛选，不传则累计）
- 响应: `{ provinces: [{ name: "广东", count: 12, projects: ["项目A", "项目B"] }] }`

**后端逻辑**: 从 `daily_reports.area` 提取省份前缀（`split('-')[0]`）进行 COUNT DISTINCT user_id 聚合

**交互**:
- 省份颜色深浅表示人员数量
- 鼠标悬停显示省份名称 + 人员数量 + 项目数
- **点击省份弹窗**: 该省人员列表（姓名、项目、区域详情、本月提交数）

**弹窗内容**:
| 列 | 说明 |
|----|------|
| 姓名 | 人员姓名 |
| 项目 | 所在项目 |
| 区域详情 | 完整 `省-市-区` |
| 本月提交 | 该人员本月审核通过的公出日志数 |

**验收标准**:
- [ ] 正确渲染中国 34 个省/自治区/直辖市/特别行政区
- [ ] 省份颜色深浅与人员数量正相关
- [ ] 点击省份弹窗显示人员详情列表
- [ ] 无数据的省份呈灰色
- [ ] 仅统计审核通过的公出日志

**小程序适配**: 因 echarts-for-weixin 地图组件包体积过大（~800KB），小程序端降级为**省份排行榜列表**。列表按人数降序排列，每行展示省份名 + 人数 + 项目数徽章，点击展开该省人员详情卡片。排行榜复用现有 `.section-card` + `.team-log-item` 列表交互模式。

## 四、数据接口设计

### 4.1 现有接口（复用）

| 接口 | 用途 | 对应需求 |
|------|------|---------|
| `POST /api/report/stats` `{ scope: 'user' }` | 个人统计 | 2.1 |

| `POST /api/report/daily-status` | 当日全员状态 | 3.4 |

| `POST /api/report/stats` `{ scope: 'project' }` | 按项目统计 | 3.2 基础数据 |

### 4.2 新增接口

| 接口 | 方法 | 用途 | 对应需求 |
|------|------|------|---------|
| `POST /api/stats/daily-counts` | 新增 | 月度每日提交人次 | 3.1 |

### 4.3 接口规范

所有接口遵循项目统一规范：
- `POST` + JSON body
- 响应格式: `{ code: 0, message: "success", data: {...} }`
- 认证: Bearer Token（JWT 中间件）
- 仅统计 `status = 'approved'` 且 `report_type != 'office'` 的记录
