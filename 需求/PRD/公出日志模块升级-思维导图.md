# 公出日志模块升级 v2.0 — 功能思维导图

> 汇报日期：2026-06-13 | 当前阶段：PRD 完成，待开发

---

```
公出日志模块升级 v2.0
│
├──────────────────────────────────────────────────────────────
│  一、日报三类型（核心填写入口）
├──────────────────────────────────────────────────────────────
│
├── 📋 公出日志 (biz_trip)
│   ├── 适用场景：每日例行外场工作记录
│   ├── 表单字段
│   │   ├── 项目名称 ★        搜索/输入
│   │   ├── 项目区域 ★        搜索/输入
│   │   ├── 关联方              历史记录选择
│   │   ├── 作业人员 ★        花名册搜索多选（新）
│   │   ├── 机型                下拉选择
│   │   ├── 工作内容            文本
│   │   ├── 需求数量 / 完成数量
│   │   ├── 今日工作小结 ★
│   │   ├── 明日计划
│   │   └── 备注
│   ├── 工作类型（六选一）
│   │   ├── 工作（陆）          正常显示全部字段
│   │   ├── 工作（海）          正常显示全部字段
│   │   ├── 待工                正常显示全部字段
│   │   ├── 在途                正常显示全部字段
│   │   ├── 请假 ──────────→ 隐藏内容区，workerIds=[] 自动略过
│   │   └── 调休 ──────────→ 隐藏内容区，workerIds=[] 自动略过
│   └── 提交流程：提交 → 自动通过 (status=approved)
│
├── 📝 补公出日志 (biz_trip_supplement)
│   ├── 适用场景：因故漏填后补录
│   ├── 表单 = 公出日志全部字段
│   ├── + 补录日期 ★          历史日期选择（不超过今天）
│   ├── + 补录原因 ★          文本说明
│   ├── 提交流程：提交 → 待审核 (status=pending_review)
│   └── 审核结果
│       ├── 判定「特殊情况」 → status=approved, timeliness=on_time（正常计数）
│       └── 判定「非特殊/忘记」→ status=approved, timeliness=delayed（延迟计数）
│
└── 📄 公司日报 (office)
    ├── 适用场景：办公室人员工作汇报
    ├── 简化表单（无项目/人员/机型等外场字段）
    │   ├── 今日工作内容 ★
    │   ├── 明日工作计划
    │   ├── 遇到的问题
    │   └── 需协调事项
    └── 特性：不入 WPS 报表视图
│
├──────────────────────────────────────────────────────────────
│  二、人员花名册（基础设施）
├──────────────────────────────────────────────────────────────
│
├── 👤 人员档案
│   ├── 独立 UID（唯一标识）
│   ├── 工号 (worker_code)
│   ├── 入场日期 (entry_date)
│   ├── 在职/离职状态 (worker_status)
│   └── 关联方单位
│
├── 🔍 选人组件（替代手敲文本）
│   ├── 搜索框（姓名/工号模糊搜索）
│   ├── 多选勾选列表
│   ├── 已选标签展示（可删除）
│   └── 数据来源：POST /api/admin/workers
│
└── 🖥️ Web 后台管理
    └── 花名册 CRUD（列表/新增/编辑/启用禁用/删除）
│
├──────────────────────────────────────────────────────────────
│  三、同组绑定（代填机制）
├──────────────────────────────────────────────────────────────
│
├── 🔗 绑定规则
│   ├── 同组 = 同关联方(related_party) + 同项目(project)
│   └── 范围：最近 30 天内有日志提交的项目
│
├── 📌 代填逻辑
│   ├── A 提交日志时勾选 B → B 当日自动标记为"已由 A 代填"
│   ├── B 打开填写页 → 检测到已被代填 → 显示代填人 + 只读查看
│   └── 去重：daily_report_workers 唯一约束 (report_id, worker_uid)
│
└── 👀 同组日志查看
    └── 统计看板中展示同组成员最近 7 天日志（只读）
│
├──────────────────────────────────────────────────────────────
│  四、补公出审核（管理功能）
├──────────────────────────────────────────────────────────────
│
├── 📋 待审核列表
│   ├── Tab：全部 / 待审核 / 已审核
│   └── 列表字段：日期、提交人、补录日期、项目、原因
│
├── ⚖️ 审核判定弹窗
│   ├── 展示：提交人、补录日期、项目、补录原因、工作内容
│   ├── 判定选项
│   │   ├── ○ 特殊情况 — 日志标记为正常
│   │   └── ○ 非特殊/忘记 — 日志标记为延迟
│   └── 审核意见（可选）
│
└── 📱 双端覆盖
    ├── 小程序：审核管理页（管理员专属）
    └── Web 后台：审核页（views/report/audit）
│
├──────────────────────────────────────────────────────────────
│  五、统计看板（数据展示）
├──────────────────────────────────────────────────────────────
│
├── 📱 小程序端 — 个人统计看板
│   ├── 顶部身份区
│   │   └── 入场日期展示
│   ├── 四格统计卡片
│   │   ├── 累计条数    156
│   │   ├── 当月条数     12
│   │   ├── 缺失天数      5
│   │   └── 延迟条数      3
│   ├── 缺失日期列表（最近 30 条）
│   └── 同组日志（最近 7 天）
│       └── 点击 → 只读详情页
│
└── 🖥️ Web 后台 — 管理统计看板
    ├── 模式一：全员汇总
    │   └── 四格卡片（总日志/本月新增/延迟条数/缺失人次）
    ├── 模式二：按项目聚合
    │   └── 表格（项目名/总条数/本月/缺失）
    └── 模式三：按人员聚合
        └── 表格（人员/总条数/本月/缺失/最近提交）
│
├──────────────────────────────────────────────────────────────
│  六、管理层看板（新增需求，可后续精进）
├──────────────────────────────────────────────────────────────
│
├── 📋 员工当日状态总览
│   ├── 后端：POST /api/report/daily-status
│   ├── 展示所有在职外场人员当日情况
│   ├── 七种状态
│   │   ├── 已提交 (submitted)
│   │   ├── 补公出 (supplement)
│   │   ├── 公司日报 (office)
│   │   ├── 已代填 (substituted)
│   │   ├── 请假 (leave)
│   │   ├── 调休 (rest)
│   │   └── ⚠ 未提交 (missing)
│   ├── 汇总统计条（各状态人数）
│   ├── 默认排序：未提交 → 已代填 → 补公出 → 已提交（异常优先）
│   ├── 小程序：统计看板「全员当日」Tab（管理员专属）
│   └── Web 后台：独立页面 views/report/daily-status
│
└── 📊 员工月度工作占比
    ├── 后端：POST /api/report/monthly-summary
    ├── 按人员 + 月份查询工作类型分布
    ├── 六类占比
    │   ├── 工作（陆）占比 + 天数
    │   ├── 工作（海）占比 + 天数
    │   ├── 待工      占比 + 天数
    │   ├── 在途      占比 + 天数
    │   ├── 请假      占比 + 天数
    │   └── 调休      占比 + 天数
    ├── 辅助信息：应出勤天数 / 已填报天数 / 缺报天数
    ├── 可视化：条形图 + 百分比
    ├── 小程序：统计看板下方「月度工作占比」区块
    └── Web 后台：独立页面 views/report/monthly-summary（可切换人员+月份）
│
├──────────────────────────────────────────────────────────────
│  七、数据变更一览
├──────────────────────────────────────────────────────────────
│
├── users 表（ALTER）
│   ├── + worker_code    VARCHAR(20)   工号
│   ├── + entry_date     DATE          入场日期
│   └── + worker_status  ENUM          在职/离职
│
├── daily_reports 表（ALTER）
│   ├── + report_type          ENUM    日志类型（新）
│   ├── + supplement_date      DATE    补录目标日期
│   ├── + supplement_reason    TEXT    补录原因
│   └── ~ MODIFY today_work_type      六种工作类型
│
├── daily_report_workers 表（CREATE ★ 新表）
│   ├── report_id  →  daily_reports.id
│   ├── worker_uid →  users.id
│   └── UNIQUE(report_id, worker_uid)  防重复
│
└── wps_reports_view（重建）
    └── 关联 daily_report_workers，排除 office 类型
│
├──────────────────────────────────────────────────────────────
│  八、API 变更
├──────────────────────────────────────────────────────────────
│
├── 改造（1个）
│   └── POST /api/report/submit          支持三种 reportType
│
└── 新增（8个）
    ├── POST /api/report/check-duplicate  检查当日是否已被代填
    ├── POST /api/report/pending-reviews  补公出日志待审核列表
    ├── POST /api/report/supplement-review 管理员审核补公出
    ├── POST /api/report/stats            三种 scope 统计看板
    ├── POST /api/report/team-logs        同组日志列表
    ├── POST /api/admin/workers           花名册 CRUD 统一入口
    ├── POST /api/report/daily-status     管理层看板 — 全员当日状态
    └── POST /api/report/monthly-summary  管理层看板 — 月度工作占比
```
