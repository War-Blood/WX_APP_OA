## 一、数据库

### 1.1 迁移脚本

路径：`sql/v2.1_attendance_migration.sql`（幂等，`IF NOT EXISTS`）

```sql
-- ============================================
-- v2.1 考勤模块数据库迁移
-- ============================================
SET NAMES utf8mb4;

CREATE TABLE IF NOT EXISTS attendance_schedules (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  user_id INT UNSIGNED NOT NULL,
  schedule_date DATE NOT NULL,
  status ENUM('work','rest','biz_trip','leave') NOT NULL DEFAULT 'work',
  note VARCHAR(200) DEFAULT NULL,
  created_by INT UNSIGNED NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id),
  FOREIGN KEY (created_by) REFERENCES users(id),
  UNIQUE KEY uk_user_date (user_id, schedule_date),
  INDEX idx_date (schedule_date),
  INDEX idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='排班日历';

CREATE TABLE IF NOT EXISTS attendance_leave_requests (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  applicant_id INT UNSIGNED NOT NULL,
  request_type ENUM('biz_trip','leave') NOT NULL,
  -- 请假字段
  leave_subtype VARCHAR(20) DEFAULT NULL,
  start_date DATE DEFAULT NULL,
  end_date DATE DEFAULT NULL,
  days DECIMAL(5,1) DEFAULT NULL,
  -- 出差字段
  trip_started_at DATETIME DEFAULT NULL,
  trip_ended_at DATETIME DEFAULT NULL,
  -- 通用字段
  reason TEXT DEFAULT NULL,
  status ENUM('active','cancelled','in_progress','ended') NOT NULL,
  source ENUM('admin','self') NOT NULL DEFAULT 'self',
  cancelled_at DATETIME DEFAULT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (applicant_id) REFERENCES users(id),
  INDEX idx_applicant_status (applicant_id, status),
  INDEX idx_type_status (request_type, status),
  INDEX idx_date_range (start_date, end_date),
  INDEX idx_trip_active (status, trip_started_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='请假申请+出差打卡';
```

## 二、API 契约

全部 `POST` + JSON body，前缀 `/api/attendance`。

### 2.1 排班

| 端点 | 权限 | 用途 |
|------|------|------|
| `POST /schedule/list` | admin | 查询排班（分页，按日期范围/部门/人员筛选） |
| `POST /schedule/upsert` | admin | 单日排班 upsert |
| `POST /schedule/batch` | admin | 批量排班（人员+日期范围+仅工作日） |

**schedule/list 请求**：`{ startDate, endDate, departmentId?, userId?, page, pageSize }`
**响应**：`{ list: [{ id, userId, userName, departmentName, scheduleDate, status, note }], total }`

**schedule/upsert 请求**：`{ userId, scheduleDate, status, note? }`
**响应**：`{ id, updated: bool }`

**schedule/batch 请求**：`{ userIds[], startDate, endDate, status, note?, weekdaysOnly? }`
**响应**：`{ inserted, updated, total }`

### 2.2 请假

| 端点 | 权限 | 用途 |
|------|------|------|
| `POST /leave/apply` | 登录用户 | 提交请假（日期范围，免审批，覆盖排班） |
| `POST /leave/my-list` | 登录用户 | 我的申请+出差列表 |
| `POST /leave/detail` | 登录用户 | 详情（含未提交日期） |
| `POST /leave/cancel` | 申请人 | 撤销请假（仅 leave，恢复排班） |

**leave/apply 请求**：`{ leaveSubtype, startDate, endDate, reason }`
**响应**：`{ requestId, days, status: 'active' }`
**校验**：`endDate < startDate` → 2806，`!leaveSubtype` → 2810
**事务**：INSERT request + 逐日 UPSERT schedules (status='leave')

**leave/my-list 请求**：`{ requestType?, status?, page, pageSize }`
**响应**：`{ list: [{ id, requestType, status, ...(leave字段|trip字段) }], total }`

**leave/detail 请求**：`{ requestId }`
**响应**：`{ id, applicantId, applicantName, requestType, (leave字段|trip字段), missingDates[]? }`
> `missingDates` 仅出差类型返回

**leave/cancel 请求**：`{ requestId }`
**校验**：biz_trip → 2813，非 active → 2805
**事务**：UPDATE status='cancelled' + 逐日恢复排班 status='work'

### 2.3 出差打卡

| 端点 | 权限 | 用途 |
|------|------|------|
| `POST /biz-trip/start` | 登录用户 | 出差开始打卡 |
| `POST /biz-trip/end` | 登录用户 | 出差结束打卡（含未提交检测） |

**biz-trip/start 请求**：`{ reason? }`
**校验**：已有 in_progress → 2811
**响应**：`{ requestId, tripStartedAt, status: 'in_progress' }`

**biz-trip/end 请求**：`{ requestId?, reason? }`
**校验**：无 in_progress → 2812
**响应**：`{ requestId, tripStartedAt, tripEndedAt, tripDays, missingDays, missingDates[], status: 'ended' }`

### 2.4 汇总

| 端点 | 权限 | 用途 |
|------|------|------|
| `POST /summary/list` | admin | 考勤汇总查询 |
| `POST /summary/export` | admin | xlsx 导出（双 Sheet + exceljs） |

**summary/list 请求**：`{ startDate, endDate, departmentId?, userId?, page, pageSize }`
**响应**：`{ list: [{ userId, userName, departmentName, workDays, restDays, bizTripDays, leaveDays, missingDays }], total }`

## 三、服务层设计

### 3.1 文件结构

```
backend/src/features/attendance/
├── routes/
│   └── attendance.routes.js     ← 5 个路由分组（schedule/leave/biz-trip/summary）
├── controllers/
│   ├── schedule.controller.js   ← 参数校验 + 调用 service
│   ├── leave.controller.js      ← 请假 + 出差 + 列表/详情
│   └── summary.controller.js    ← 汇总 + 导出
└── services/
    ├── schedule.service.js      ← 排班 CRUD + 批量
    ├── leave.service.js         ← 请假申请/撤销/列表/详情
    ├── trip.service.js          ← 出差开始/结束 + 未提交检测
    └── summary.service.js       ← 汇总统计 + exceljs 导出
```

### 3.2 schedule.service.js

```js
async function list({ startDate, endDate, departmentId, userId, page, pageSize })
  → JOIN users + departments，分页返回排班记录

async function upsert({ userId, scheduleDate, status, note, createdBy })
  → INSERT ... ON DUPLICATE KEY UPDATE

async function batch({ userIds, startDate, endDate, status, note, weekdaysOnly, createdBy })
  → 展开日期范围（weekdaysOnly 过滤周六日），逐日 upsert
  → 返回 { inserted, updated, total }
```

### 3.3 leave.service.js

```js
async function apply({ applicantId, startDate, endDate, leaveSubtype, reason })
  → 事务:
    1. INSERT request (status='active', leave 字段)
    2. 逐日 UPSERT schedules (status='leave')
  → 返回 { requestId, days, status }

async function myList({ applicantId, requestType, status, page, pageSize })
  → 查自己的 leave + biz_trip 记录，分页

async function detail(requestId)
  → JOIN users 取申请人信息
  → 若是 in_progress biz_trip → 计算 missingDates

async function cancel(requestId, applicantId)
  → 事务:
    1. UPDATE request SET status='cancelled'
    2. 逐日恢复 schedules SET status='work'
```

### 3.4 trip.service.js

```js
async function startTrip({ applicantId, reason })
  → 检查已有 in_progress → 2811
  → INSERT request (status='in_progress', trip_started_at=NOW())

async function endTrip({ applicantId, requestId, reason })
  → 查 in_progress 记录 → 无则 2812
  → 计算 missingDays:
    for date in [trip_started_at, today]:
      hasReport ← SELECT daily_reports WHERE user_id, date, status='approved', report_type!='office'
      hasLeave  ← SELECT attendance_leave_requests WHERE applicant_id, 'leave', 'active', date BETWEEN start/end
      if !hasReport && !hasLeave → missingDates.push(date)
  → UPDATE trip_ended_at=NOW(), status='ended'
  → 返回 { tripDays, missingDays, missingDates }
```

### 3.5 summary.service.js

```js
async function list({ startDate, endDate, departmentId, userId, page, pageSize })
  → 查 users（在职，status='active'）
  → 逐人逐日:
    1. 查 daily_reports（status='approved'）→ get todayWorkType
    2. 查 attendance_schedules → get status
    3. 查 attendance_leave_requests（active biz_trip + leave）
    4. 优先级: daily_reports > schedules
    5. 出差未提交: 处于 in_progress + 无 report + 无 leave → missingDays++

async function exportExcel({ startDate, endDate, departmentId, userId })
  → exceljs 双 Sheet 生成（参照 PRD 伪代码）
  → 返回 { buffer, filename }
```

## 五、错误处理

| 错误码 | 场景 | HTTP |
|:--:|------|:--:|
| 2801 | 同一人同天重复排班（已被 upsert 处理，实际不抛出） | 200 |
| 2802 | 申请单不存在 | 200 |
| 2805 | 已撤销不可重复撤销 | 200 |
| 2806 | 结束日期早于起始日期 | 200 |
| 2810 | 请假未指定子类型 | 200 |
| 2811 | 已有进行中出差 | 200 |
| 2812 | 无进行中出差 | 200 |
| 2813 | 出差不可撤销 | 200 |

全部业务错误 HTTP 200，通过 `code` 区分。Service 层抛 `BusinessError`，Controller 层透传给 `next(err)`。
