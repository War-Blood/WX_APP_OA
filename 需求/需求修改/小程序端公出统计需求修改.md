# 小程序端公出统计 — 区域分布（昨日）需求规格

> 状态：待实现  
> 日期：2026-06-27

---

## 一、功能定位

「人员分布」Tab 下的「区域分布（昨日）」模块，展示昨天全国各省的外场人员分布情况。

**数据口径**：只看昨日，`status = 'approved'` 且 `report_type != 'office'`。

---

## 二、数据来源

一个人员属于某个省份，通过以下三条路径判定（任一条满足即计入）：

| 路径 | 数据表 | 逻辑 |
|------|--------|------|
| ① 直接提交 | `daily_reports.user_id` | 自己提交了该省的日志 |
| ② 关联代填 | `daily_report_workers.worker_uid` | 被代填到该省的日志中 |
| ③ 文本匹配 | `daily_reports.workers` 字段 | 日志的 workers 文本中列出其名，匹配到 `users` 表 |

**去重规则**：同一人 + 同一省份 + 同一日期 → 只计一次。

**关键约束**：
- 每人单日最多一条日志（自己提交或他人代填），不存在同一人多省的情况
- area 字段来源为地点选择框，格式固定为 `省-市-县`

---

## 三、API 设计

### 3.1 区域分布面板

```
POST /api/stats/area-distribution
Request:  { month?: string }   // 可选，当前固定查昨日
Response: {
  date: "2026-06-26",
  provinces: [
    {
      name: "广东省",
      count: 5,                           // 该省人数
      projects: ["项目A", "项目B"],        // 该省涉及的项目（去重，最多10个）
      workers: [
        { userId: 1, userName: "张三", workerCode: "GZ001" },
        ...
      ]
    },
    ...
  ]
}
```

**排序**：按 `count` 降序。

### 3.2 省份下钻

```
POST /api/stats/province-workers
Request:  { province: "广东省" }
Response: {
  province: "广东省",
  workers: [
    { userId: 1, userName: "张三", workerCode: "GZ001", project: "项目A", area: "广东省-广州市" },
    ...
  ]
}
```

**约束**：`workers.length` 必须与面板中该省的 `count` 一致。

## 四、小程序 UI

### 4.1 面板

```
┌─────────────────────────────────┐
│ 区域分布（昨日）                  │
├─────────────────────────────────┤
│  广东省        张三、李四、王五    │
│  江苏省        赵六、钱七         │
│  广西壮族自治区  孙八             │
│  ...                           │
└─────────────────────────────────┘
```

- 左列：省份名（`area.split('-')[0]`）
- 右列：该省人员姓名，用 `、` 连接
- 点击某省 → 弹出下钻弹窗

### 4.2 下钻弹窗

```
┌─────────────────────────────────┐
│ 广东省 · 3人                    ✕ │
├─────────────────────────────────┤
│  张三    GZ001   项目A           │
│  李四    GZ002   项目A           │
│  王五    GZ003   项目B           │
└─────────────────────────────────┘
```

- 标题：`省份名 · N人`
- 每行：姓名 + 工号 + 所属项目
- 点击某行 → 跳转日志详情

### 4.3 空状态

当日无数据时显示「暂无数据」。

## 五、边界情况

| 场景 | 处理 |
|------|------|
| area 为空或 NULL | 跳过 |
| area 不含 `-`（非标准格式） | 跳过（数据已清洗，作为兜底） |
| workers 文本中名字无法匹配到 users 表 | 跳过该名字 |
| 同一人在同一省被多条路径命中 | 只计一次，project 合并 |
| 省份列表为空 | 面板显示「暂无数据」 |

## 六、实现方案

### 6.1 后端

**文件**：`backend/src/core/services/stats.service.js`

`getAreaDistribution` 重写，核心逻辑：

```
1. 查昨日所有 approved 日志（area 非空）
2. 查昨日关联表代填记录
3. 构建 name→uid 映射（全量 field_worker）
4. 三路径收集：personMap[key = uid + province]
   - path 1: reports.user_id → 取 area 省份
   - path 2: subs.worker_uid → 取 area 省份
   - path 3: reports.workers 文本 → 名字匹配 uid → 取 area 省份
5. 按 province 聚合：count、projects、workers
6. 按 count 降序返回
```

`getProvinceWorkers` 重写，与 `getAreaDistribution` 共享同一套三路径逻辑，仅 SQL 范围缩小为单省。

### 6.2 前端

**文件**：`miniapp/src/pages/profile/stats.vue`

- `loadAreas()` 调用 `getAreaDistribution()` 获取面板数据
- `openProvinceDrill(p)` 调用 `getProvinceWorkers(p.name)` 获取下钻数据
- 下钻弹窗展示已有组件（`drill-overlay` / `drill-panel`），无需新建
