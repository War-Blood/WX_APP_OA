# 小程序端公出统计需求修改

> 更新：2026-06-27

---

## 问题所在

### 1. 省份下钻需要显示所有在该区域的人

点开省份后需要显示所有在这个区域的人，无论是否为待填。待填人的日志链接到填写人上就行。

**状态**：✅ 已修复（`309cfe7`）

`getProvinceWorkers` 原只查直接提交人（`JOIN users ON dr.user_id = u.id`），现在改为与 `getAreaDistribution` 一致的三路径查人：直接提交人 + `daily_report_workers` 关联表 + `workers` 文本字段匹配。

---

### 2. 区域划分只显示省份，但仍能看到县和区

例如能看到"安徽省亳州市坛城县"这种非标准格式。

**状态**：✅ 已修复 — 分两层解决

| 层 | 修复 |
|----|------|
| 代码层 (`309cfe7`) | `getAreaDistribution` 的 `addPerson` 增加 `if (!area.includes('-')) return;` 过滤非标准格式 |
| 数据层 (`2026-06-27`) | 数据库清洗：6月后 **325 条**无 `-` 的脏 area 全部整改为标准"省-市-县"格式 |

**根因**：部分历史 area 数据没有按照省市县格式填写（缺横线、省份简称、混入公司名等），代码取 `area.split('-')[0]` 时这些脏数据被当作整体，到前端显示时出现完整字符串。

---

### 3. 面板人数与下钻人数不一致

点开广东省能看到三个人，但是外面只显示两人。

**状态**：✅ 根因已定位，数据库已清洗，待验证

**根因诊断**：

经过排查，问题出在数据库 area 字段存在大量非标准格式数据。并非之前怀疑的"跨省去重"逻辑问题——因为：

- 每人单日只能上传一次日志（提交或代填，二选一）
- 地点通过选择框填写，同一人不会出现在多个省份

真正的机制是：

```
脏数据示例: "广东阳江"（无 '-' 分隔符）

getAreaDistribution 面板:
  addPerson() 中 if (!area.includes('-')) return;
  → "广东阳江" 被直接丢弃 → 提交人未计入任何省份 → 面板少人

getProvinceWorkers 下钻:
  SQL: WHERE dr.area LIKE '广东-%'
  → "广东阳江" 不以 '广东-' 开头 → 查不到该条报告本身
  
  但该报告中 workers 字段列出的其他人名，
  可能在其他报告中通过 path 2/3 被找到 → 下钻多出人来

结果: 面板 2 人, 下钻 3 人
```

---

## 根因总结

**根本原因不是代码去重逻辑，而是数据库 area 字段的脏数据。**

| 项目 | 数值 |
|------|:--:|
| 6月+ 无 `-` 的脏 area 记录 | 325 条 |
| 脏数据模式种类 | 32 种 |
| 典型问题 | 缺省份前缀、省份简称、缺横线、省名错误、混入公司名 |
