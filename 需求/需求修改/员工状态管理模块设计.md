# 员工状态管理模块 — 功能设计文档

> 版本: v1.0 | 状态: 设计中 | 2026-06-26

---

## 一、背景

当前请假/调休通过公出日志表单提交，操作流程与正常公出日志混在一起，导致：
- 请假要填起止日期+备注，但表单仍显示项目/人员/工作量等无关节
- 生成的是"公出日志"记录（`report_type=biz_trip`），语义不清晰
- 管理员无法统一查看/管理员工状态

**目标**：独立出一个员工状态模块，管理员统一设定，统计自动识别。

---

## 二、核心概念

### 2.1 四种员工状态

| 状态 | 含义 | 是否需要提交日报 | 统计行为 |
|------|------|:--:|------|
| **出差** | 外出工作 | ✅ 必须 | 检查公出日志是否已提交，未提交→缺报 |
| **请假** | 请假 | ❌ 自动 | 每天自动生成 1 条请假记录 |
| **调休** | 调休 | ❌ 自动 | 每天自动生成 1 条调休记录 |
| **公司** | 办公室办公 | ❌ 自动 | 每天自动生成 1 条公司日报记录 |

### 2.2 与公出日志的关系

```
管理员设置状态
    ↓
系统每天凌晨/实时检查
    ↓
┌─ 出差 → 检查该员工当日是否已提交公出日志
│         已提交 → 正常
│         未提交 → 标记缺报
│
├─ 请假 → 自动 INSERT 一条 daily_reports
│         report_type=biz_trip, today_work_type=请假, status=approved
│
├─ 调休 → 同上，today_work_type=调休
│
└─ 公司 → 自动 INSERT 一条 daily_reports
          report_type=office, status=approved
```

## 三、数据设计

### 3.1 新表：`employee_status`

```sql
CREATE TABLE employee_status (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  user_id INT UNSIGNED NOT NULL,
  status VARCHAR(20) NOT NULL COMMENT '出差/请假/调休/公司',
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  remark VARCHAR(500) DEFAULT NULL COMMENT '备注原因',
  created_by INT UNSIGNED COMMENT '设置人',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_user_date (user_id, start_date, end_date)
);
```

### 3.2 与现有表的关系

```
employee_status (新)
    ↓ user_id
users
    ↓ id
daily_reports (现有，自动生成的记录)
```

## 四、API 设计

### 4.1 设置员工状态

```
POST /api/admin/employee-status/set
```

**请求**：
```json
{
  "userId": 14,
  "status": "请假",
  "startDate": "2026-06-26",
  "endDate": "2026-06-28",
  "remark": "家里有事"
}
```

**响应**：
```json
{
  "code": 0,
  "data": {
    "statusId": 1,
    "generatedDays": 3,
    "skippedDates": []
  }
}
```

### 4.2 查询员工当前状态

```
POST /api/admin/employee-status/current
```

**请求**：`{ "userId": 14, "date": "2026-06-26" }`

**响应**：
```json
{
  "code": 0,
  "data": {
    "status": "请假",
    "startDate": "2026-06-26",
    "endDate": "2026-06-28",
    "remark": "家里有事"
  }
}
```

### 4.3 批量查询当日全员状态

```
POST /api/admin/employee-status/daily
```

**请求**：`{ "date": "2026-06-26" }`

**响应**：返回当日所有设置了状态的员工列表（已可复用现有 `/api/report/daily-status`）

### 4.4 取消/修改状态

```
POST /api/admin/employee-status/cancel
POST /api/admin/employee-status/update
```

## 五、前端设计

### 5.1 Web 管理后台 — 员工状态管理页

新增页面：`/employee-status`

| 功能 | 说明 |
|------|------|
| 状态列表 | 表格：姓名、当前状态、起止日期、备注、设置人、操作 |
| 设置状态 | 弹窗：选人、选状态（出差/请假/调休/公司）、起止日期、备注 |
| 取消状态 | 删除状态记录 + 清除已生成的自动日志 |

### 5.2 小程序 — 无需改动

员工端不需要操作，状态由管理员统一设置。
公出统计/全员当日状态已有对应展示逻辑。

### 5.3 小程序 — 公出统计增强

全员当日状态页已有 请假/调休/公司日报 分类展示。
新增：员工卡片上显示状态来源（"管理员设置"标记）。

## 六、定时任务

每天凌晨执行（或实时触发）：

```
for each employee_status WHERE start_date <= today <= end_date:
    if 当日 daily_reports 已存在:
        skip
    else:
        INSERT daily_reports (根据 status 填对应字段)
```

### 6.1 自动生成字段对照

| 状态 | report_type | today_work_type | project | workers |
|------|------------|----------------|---------|---------|
| 出差 | — | — | — | —（人工提交） |
| 请假 | `biz_trip` | `请假` | `请假` | 员工姓名 |
| 调休 | `biz_trip` | `调休` | `调休` | 员工姓名 |
| 公司 | `office` | NULL | NULL | 员工姓名 |

其余字段均为 NULL/0（与正常公出日志结构一致 28 列）。

## 九、与旧方案对比

| | 旧方案（当前） | 新方案 |
|------|------|------|
| 操作人 | 员工自己提交 | 管理员统一设置 |
| 操作位置 | 公出日志表单选"请假" | 独立状态管理页 |
| 记录生成 | 提交时批量 INSERT | 定时任务自动生成 |
| 撤销 | 需手动删除记录 | 取消状态即清除 |
| 公司日报 | 员工每天手动提交 | 设"公司"状态后自动生成 |
