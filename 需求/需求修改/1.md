# GitHub 分支保护上传框架

> 规则文件：`.AI/rules/git-workflow.md`（已有完整规范，本文档是落地步骤）

---

## 一、分支模型

```
feature/fix → test → stable → main
   ↑ AI 开发    ↑ AI push   ↑ 用户手动  ↑ 用户手动
```

| 分支 | 用途 | 谁可以 push |
|------|------|:--:|
| `main` | 生产就绪代码 | 用户手动 |
| `stable` | 验证通过的稳定版本 | 用户手动 |
| `test` | 功能集成测试环境 | AI + 用户 |
| `feature/xxx` | 功能开发 | AI 本地 |
| `fix/xxx` | Bug 修复 | AI 本地 |

## 二、一次性初始化（你来执行）

### 2.1 本地创建分支结构

```bash
cd Y:\AI\WX-APP-OA

# 从 main 创建 stable 和 test
git checkout main
git checkout -b stable
git checkout main
git checkout -b test

# 推送新分支到 GitHub
git push WX_APP_OA stable
git push WX_APP_OA test
```

### 2.2 GitHub 上设置分支保护

打开 https://github.com/War-Blood/WX_APP_OA/settings/branches

**main 分支规则**（Add classic branch protection rule）：
- Branch name pattern: `main`
- ✅ Require a pull request before merging
- ✅ Require approvals (1)
- ✅ Require status checks to pass before merging
- ❌ Do not allow bypassing the above settings

**stable 分支规则**（同上）：
- Branch name pattern: `stable`
- ✅ Require a pull request before merging
- ❌ 不允许直接 push

### 2.3 验证

```bash
# 确认分支结构
git branch -a

# 应该看到:
# * main
#   stable
#   test
#   remotes/WX_APP_OA/main
#   remotes/WX_APP_OA/stable
#   remotes/WX_APP_OA/test
```

## 三、AI 开发流程（日常）

### 步骤 1：创建功能分支

```bash
git checkout test
git pull WX_APP_OA test
git checkout -b feature/新功能名
```

### 步骤 2：开发 + 提交

AI 在 feature 分支上写代码，每次改动后自动 commit 到本地。

### 步骤 3：推到 test 验证

```bash
# AI 或你说"推到测试"
git checkout test
git merge feature/新功能名
git push WX_APP_OA test

# 部署到服务器验证
```

### 步骤 4：验证通过后合并到 stable（你手动）

```bash
git checkout stable
git merge test
git push WX_APP_OA stable
```

### 步骤 5：发布到 main（你手动）

在 GitHub 上创建 PR：`stable` → `main`，审核后合并。

## 四、紧急修复流程

```bash
git checkout main
git checkout -b hotfix/问题描述
# ... 修复 ...
git checkout test
git merge hotfix/问题描述
git push WX_APP_OA test
# 验证通过后
git checkout stable
git merge test
git checkout main
git merge stable
```

## 五、AI 权限边界

| 操作 | 本地 | 远程 |
|------|:--:|:--:|
| commit | ✅ | — |
| push test | — | ✅ |
| push stable | — | ❌ |
| push main | — | ❌ |
| push --force（任何分支） | — | ❌ |
| merge 到 stable/main | ❌ | ❌ |

## 六、模板检查清单

每次 push test 前确认：

- [ ] `npm run lint` / `npm run type-check` 通过
- [ ] 无硬编码密钥、密码、token
- [ ] 无 console.log / debugger 残留
- [ ] commit message 格式正确：`type(scope): 中文描述`
- [ ] 代码已在服务器上验证通过
