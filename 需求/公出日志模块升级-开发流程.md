详见 `sql/` 目录，新建 `sql/v2.0_migration.sql`：

```sql
-- v2.0 公出日志模块升级 — 数据库迁移
-- 执行前备份: mysqldump wx_app_oa > backup_$(date +%Y%m%d).sql

ALTER TABLE users 
  ADD COLUMN worker_code VARCHAR(20) COMMENT '工号',
  ADD COLUMN entry_date DATE COMMENT '入场日期',
  ADD COLUMN worker_status ENUM('active','inactive') DEFAULT 'active' COMMENT '外场人员状态';

ALTER TABLE daily_reports 
  ADD COLUMN report_type ENUM('biz_trip','biz_trip_supplement','office') 
    DEFAULT 'biz_trip' COMMENT '日志类型',
  ADD COLUMN supplement_date DATE COMMENT '补录目标日期',
  ADD COLUMN supplement_reason TEXT COMMENT '补录原因',
  MODIFY today_work_type VARCHAR(20) COMMENT '今日工作类型: 工作（陆）/工作（海）/待工/在途/请假/调休';

CREATE TABLE daily_report_workers (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  report_id INT UNSIGNED NOT NULL,
  worker_uid INT UNSIGNED NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (report_id) REFERENCES daily_reports(id) ON DELETE CASCADE,
  FOREIGN KEY (worker_uid) REFERENCES users(id),
  UNIQUE KEY uk_report_worker (report_id, worker_uid)
);
```

### 1.1 日报提交改造 `POST /api/report/submit`

**文件**: `backend/src/core/services/report.service.js` + `backend/src/core/controllers/report.controller.js`

**改造内容**:

```
当前 submit() 逻辑:
  1. 校验字段 → 2. 写入 daily_reports(workers 文本字段) → 3. 返回 reportId

改造后 submit() 逻辑:
  1. Joi 校验(按 reportType 区分必填字段)  ← controller 层
  2. 补充 entryDate/initialBizTripDate      ← 如前端未传，从 users 表查
  3. 检查是否已被代填                         ← 查 daily_report_workers
     → 已代填返回 code 2001
  4. 请假/调休: workerIds=[] 跳过代填
  5. 写入 daily_reports(report_type 判断字段集)
  6. workerIds 非空 → 批量 INSERT daily_report_workers(事务)
  7. biz_trip_supplement → status='pending_review'
     其他 → status='approved'
  8. 返回 reportId
```

**新增 Joi 校验规则**:

| reportType | 必填字段 | 可选字段 |
|------------|---------|---------|
| `biz_trip` | project, area, workerIds, todayWork | 其余所有 |
| `biz_trip_supplement` | 同上 + supplementDate, supplementReason | 其余所有 |
| `office` | todayWork | tomorrowPlan, issues, coordination |

**todayWorkType = 请假/调休 时**: project/area/workerIds 允许为空

**需要处理的关键细节**:
- `workers` 旧字段不再写入（保留兼容读取）
- 事务：daily_reports INSERT + daily_report_workers 批量 INSERT 在同一事务中
- 错误处理：事务回滚 + 返回明确错误信息

**3.1.3 审核判定核心逻辑**:
```js
// supplement-review service
async function reviewSupplement(reportId, decision, comment, reviewerId) {
  const timeliness = decision === 'special' ? 'on_time' : 'delayed'
  await db.execute(
    `UPDATE daily_reports SET status = 'approved', timeliness = ?, updated_at = NOW() WHERE id = ?`,
    [timeliness, reportId]
  )
  // 写入 review_records 审核记录
  await db.execute(
    `INSERT INTO review_records (report_id, reviewer_id, action, opinion, created_at) VALUES (?, ?, ?, ?, NOW())`,
    [reportId, reviewerId, decision, comment || null]
  )
  return { timeliness }
}
```

**3.1.5 当日状态计算逻辑**:
```
1. 查 users WHERE worker_status = 'active' → 所有在职人员
2. 查 daily_reports WHERE report_date = 今天 → 当日提交
3. 查 daily_report_workers → 代填关系
4. 逐人判定 status:
   - 有 biz_trip 日志 → submitted(substituted 如由人代填)
   - 有 biz_trip_supplement → supplement
   - 有 office → office
   - today_work_type='请假' → leave
   - today_work_type='调休' → rest
   - 无任何记录 → missing
5. 汇总 → summary
```

## 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| **workers 文本字段迁移** | 历史数据 workers 是文本，新系统用关联表 | 保留 workers 字段只读，新数据走 daily_report_workers |
