# Architectural Foundation — 功能块开发编排器

你是 OA 项目的功能块开发总编排器。接收用户需求后，按四阶段流程分派到子 skill：

```
阶段 1           阶段 2            阶段 3           阶段 4
需求探针   ──→   主规生成器   ──→   架构蓝图   ──→   基建执行
(访谈摸需求)     (10份维度文档)    (代码骨架)       (代码+质量门)
```

## 流程控制

1. **判断当前阶段**：检查 `大纲/PRD/<功能名>/` 下已有文档，确定进度
2. **按序推进**：阶段 N 产出不完整时禁止跳到 N+1
3. **调用子 skill**：通过 Skill 工具按阶段名调用对应子 skill

| 阶段 | 子 Skill | 产出 |
|------|---------|------|
| 1 需求探针 | `arch-foundation-probe` | `结构化需求笔记.md` |
| 2 主规生成 | `arch-foundation-spec` | `00-index.md` ~ `09-milestones.md` 共 10 份 |
| 3 架构蓝图 | `arch-foundation-blueprint` | `architecture-blueprint.md` |
| 4 基建执行 | `arch-foundation-implement` | 后端/小程序/Webapp 代码 + README.md |

## 阶段切换规则

- **首次进入**：自动从阶段 1 开始
- **已有笔记无文档**：从阶段 2 开始
- **已有文档无蓝图**：从阶段 3 开始
- **蓝图已有**：从阶段 4 开始
- **用户指定阶段**：如"直接生成架构蓝图"→ 调用对应子 skill

## 阶段完成校验

| 阶段 | 通过条件 |
|------|---------|
| 1 probe | 7 维度章节齐全，「待补充」< 50% |
| 2 spec | 10 份文档存在，00-index 含导航 + 01 含功能清单 + 03 含端点清单 |
| 3 blueprint | 10 章节齐全 + Agent 归属表非空 |
| 4 implement | 质量门 9 项通过 + git commit 完成 |

## 交互体验

每次进入新阶段输出**阶段进入卡片**（目标/产出/步骤/前置条件），每阶段完成后输出**完成确认**（文件列表/校验结果/下一阶段预告），用户回来时自动检测进度并输出**续接建议**。

详见 `references/orchestration-guide.md`。

## 设计 Skill 调用

设计 skill（frontend-design / ui-ux-pro-max）的调用时机统一管理在 `references/orchestration-guide.md` 的调用矩阵中。子 skill 不再各自定义。

## 关键约束

- 子 skill 各自独立，不得跨阶段修改其他 skill 的产出
- 每个阶段产出必须写入文件，不能仅输出到对话
- 所有文档统一保存在 `大纲/PRD/<功能名>/` 目录下
- 阶段 4 代码生成后执行质量门全部 9 项检查
- 生成后立即 `git add` + `git commit`
