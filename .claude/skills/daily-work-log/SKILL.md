# 每日工作日志生成

## 触发时机

- 每次代码改动 + 提交 + 部署完成后
- 用户说"生成日志"、"写工作日志"、"记录今天的工作"
- 会话结束前（如果期间有代码改动）

## 输出路径

```
需求/任务日志/YYYY-MM-DD.md
```

如果该日文件已存在，追加新内容（在已解决和待处理表格中追加行，不覆盖已有记录）。

## 日志模板

严格按照以下格式输出：

```markdown
# 工作日志 — YYYY-MM-DD

---

## 完成事项

| # | 事项 | 涉及文件 | 提交 |
|:--:|------|------|------|
| 1 | 事项描述 | 文件1, 文件2 | `commithash` |

## 部署状态

| 层 | 状态 | 备注 |
|------|:--:|------|
| 后端 | ✅/❌ | PM2 重启 / 未部署 |
| 小程序 | ✅/❌ | 已构建 / 未构建 |
| Webapp | ✅/❌ | 已构建 / 未构建 |

## 验证结果

- 验证项 1 ✅/❌
- 验证项 2 ✅/❌

## 待处理

- [ ] 待处理项 1
- [ ] 待处理项 2

---

*自动生成*
```

## 工作流程

1. **收集信息**：回顾当前会话的 git log（`git log --oneline -10`），找出本次会话的新提交
2. **汇总事项**：按提交分组，概括每个提交做了什么
3. **检查状态**：确认后端是否部署（PM2 restart）、小程序是否构建（build:mp-weixin）、Webapp 是否构建
4. **记录验证**：如果有 API 测试/手动验证的结果，记录下来
5. **列出待办**：未完成的事项、未部署的代码、需要人工验证的项目
6. **写入文件**：写入 `需求/任务日志/YYYY-MM-DD.md`，如已有则追加

## 注意事项

- commit hash 取短格式（7 位，如 `be4b230`）
- 事项描述使用中文，简洁明了（15 字以内）
- 如果某层未改动，标注"无需"而非"未部署"
- 模板参考文件：`references/template.md`
