- ❌ 不修改 `daily_reports` 表结构

- ✅ 现有功能和新模块并行运行，互不干扰

## 一、概述

独立于公出日志的员工状态管理模块。管理员统一设置每个员工的状态（出差/请假/调休/公司），新模块根据状态自动统计，不影响现有日志体系。

### 四种状态

| 状态 | 含义 | 统计行为 |
|------|------|------|
| **出差** | 外出工作 | 检查该员工当日是否已提交公出日志 |
| **请假** | 请假中 | 当日自动计为请假 |
| **调休** | 调休中 | 当日自动计为调休 |
| **公司** | 办公室办公 | 当日自动计为公司办公 |

### 与现有系统的关系

```
现有系统（不动）                    新模块（独立）
─────────────                    ──────────
daily_reports                    employee_status（新表）
    ↓                                ↓
公出统计 / 全员当日              员工状态统计（新页面）
日志填写 / 提交                   状态设置（新页面）
```

## 二、数据设计

### 2.1 新表：`employee_status`

```sql
CREATE TABLE employee_status (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  user_id INT UNSIGNED NOT NULL COMMENT 'FK→users.id',
  status VARCHAR(20) NOT NULL COMMENT '出差/请假/调休/公司',
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  remark VARCHAR(500) DEFAULT NULL,
  created_by INT UNSIGNED COMMENT '设置人',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_user_date (user_id, start_date, end_date)
);
```

### 2.2 查询逻辑（不写入 daily_reports）

当需要判断某个员工某天的状态时：

```sql
SELECT status FROM employee_status
WHERE user_id = ?
  AND start_date <= '查询日期'
  AND end_date >= '查询日期'
ORDER BY created_at DESC LIMIT 1
```

统计时直接从 `employee_status` 表实时查询，**不生成 daily_reports 记录**。

## 三、API 设计

全部新路由，前缀 `/api/status/*`：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/status/set` | 设置/更新员工状态 |
| POST | `/api/status/cancel` | 取消状态 |
| POST | `/api/status/current` | 查单个员工当前状态 |
| POST | `/api/status/daily` | 当日全员状态汇总（新统计用） |
| POST | `/api/status/list` | 状态历史列表（管理页用） |

## 四、前端设计

### 4.1 Web 管理后台 — 状态管理页

新路由：`/status`

- 表格：姓名、状态、起止日期、备注、设置人、操作
- 弹窗：选人 → 选状态 → 起止日期 → 备注 → 确定
- 取消：删除该状态记录

### 4.2 Web 管理后台 — 状态统计页（新）

新路由：`/status/stats`

- 当日状态汇总卡片：出差 X人 / 请假 X人 / 调休 X人 / 公司 X人
- 人员明细列表（点击可查看详情）
- 按日期导航（前一天/后一天）
- **完全独立于现有的公出统计页面**

### 4.3 小程序 — 状态查看（新）

在功能中心新增入口「员工状态」，显示当日全员状态汇总。
