# 考试模块 — OA 架构适配方案

> 基于 SpringBoot+UniApp 刷题系统框架，适配到 OA 项目 Node.js + uni-app + Vue3 架构

---

## 一、模块定位

在 OA 系统中新增**在线考试**功能模块，分为两大核心场景：

| 场景               | 说明                                     | OA 中定位              |
| ------------------ | ---------------------------------------- | ---------------------- |
| **模拟自测** | 自由刷题、即时纠错、反复练习、无时间约束 | 小程序 → 员工自助学习 |
| **正式考试** | 限时答题、固定试卷、自动判分、成绩存档   | 小程序 → 企业考核测评 |

## 二、数据库设计

### 新增表（5 张）

```sql
-- 题库分类表（树形结构）
CREATE TABLE exam_categories (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  parent_id INT UNSIGNED DEFAULT 0 COMMENT '父级ID, 0=顶级',
  name VARCHAR(50) NOT NULL COMMENT '分类名称',
  path VARCHAR(200) COMMENT '路径 如 安全/生产安全/电气安全',
  sort_order INT DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='题库分类';

-- 题库表
CREATE TABLE exam_questions (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  category_id INT UNSIGNED COMMENT '分类ID（关联 exam_categories）',
  type ENUM('single','multiple','judge') NOT NULL DEFAULT 'single' COMMENT '题型: 单选/多选/判断',
  title TEXT NOT NULL COMMENT '题干',
  options JSON NOT NULL COMMENT '选项 [{key:"A",text:"..."}]',
  answer VARCHAR(20) NOT NULL COMMENT '正确答案（多选用逗号分隔如 A,B）',
  analysis TEXT COMMENT '解析',
  score INT NOT NULL DEFAULT 2 COMMENT '分值',
  score_mode ENUM('exact','partial') DEFAULT 'exact' COMMENT '多选评分: exact=全对才得分, partial=漏选给半分',
  status ENUM('active','disabled') DEFAULT 'active',
  created_by INT UNSIGNED COMMENT '创建人',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='考试题库';

-- 试卷表
CREATE TABLE exam_papers (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  title VARCHAR(200) NOT NULL COMMENT '试卷名称',
  description TEXT COMMENT '试卷说明',
  duration INT NOT NULL DEFAULT 60 COMMENT '考试时长（分钟）',
  pass_score INT NOT NULL DEFAULT 60 COMMENT '合格分数',
  total_score INT NOT NULL DEFAULT 100 COMMENT '总分',
  max_attempts INT DEFAULT 1 COMMENT '每人可考次数, 0=无限',
  max_screenshot_warns INT DEFAULT 2 COMMENT '截屏警告上限, 超限强制交卷',
  question_ids JSON NOT NULL COMMENT '题目ID数组 [1,2,3,...]',
  status ENUM('draft','published','archived') DEFAULT 'draft',
  version INT DEFAULT 1 COMMENT '版本号, 修改时+1',
  created_by INT UNSIGNED,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='考试试卷';

-- 考试记录表
CREATE TABLE exam_records (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  user_id INT UNSIGNED NOT NULL COMMENT '考生',
  paper_id INT UNSIGNED NOT NULL COMMENT '试卷',
  paper_version INT COMMENT '试卷版本号',
  mode ENUM('practice','exam') NOT NULL DEFAULT 'practice' COMMENT '模式: 练习/考试',
  answers JSON COMMENT '用户答案 {"1":"A","2":"B,C"}',
  question_snapshot JSON NOT NULL COMMENT '试卷快照 — 考试开始时冻结的完整题目数据',
  score INT DEFAULT NULL COMMENT '得分',
  total_score INT NOT NULL COMMENT '试卷总分',
  is_pass TINYINT(1) DEFAULT NULL COMMENT '是否合格',
  warn_count INT DEFAULT 0 COMMENT '截屏警告次数',
  server_time DATETIME COMMENT '服务器开始时间（用于倒计时校验）',
  start_time DATETIME NOT NULL COMMENT '开始时间',
  end_time DATETIME COMMENT '交卷时间',
  status ENUM('doing','submitted','timeout','cheated') DEFAULT 'doing',
  UNIQUE KEY uk_user_paper_doing (user_id, paper_id) COMMENT '每人每卷仅一条进行中记录（需应用层配合先清僵尸）',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='考试记录';
```

## 七、关键业务逻辑

### 正式考试流程（含快照+防并发）

```
小程序请求 /exam/exam/start { paperId }
  → 后端：
    1. 查询试卷状态 = 'published'
    2. 检查是否已有 doing 记录（通过 uk_user_paper_doing 唯一索引）
      如有僵尸记录先 UPDATE SET status='timeout'
    3. 组装 question_snapshot：
       将 question_ids 对应的完整题目（题干/选项/答案/分值/评分模式）
       序列化为 JSON，存入 exam_records
    4. 记录 server_time = NOW()，开始计时
    5. 返回 { recordId, snapshot, serverTime, duration }
  → 前端以 serverTime 为基准启动倒计时

小程序请求 /exam/exam/submit { recordId, answers }
  → 后端：
    1. 强制校验 NOW() < (server_time + INTERVAL duration MINUTE)，超时拒收
    2. 基于 question_snapshot 判分（不查实时题库，确保数据一致性）
    3. 更新 score, is_pass, end_time, status='submitted'
```

### 防作弊体系

1. **并发防重复**：
   - 应用层：先 `UPDATE ... SET status='timeout' WHERE status='doing' AND user_id=? AND paper_id=?` 清僵尸记录
   - 数据库层：`UNIQUE KEY uk_user_paper_doing (user_id, paper_id)` 兜底
2. **计时不可信防御**：
   - 后端强制校验 `NOW() < server_time + duration`，超时拒收提交
   - 前端倒计时以 `serverTime` 为基准，非本地时间
   - 超时未提交 → 后端定时任务扫描 status='doing' 且 NOW() > server_time+duration → 自动 timeout
3. **断线恢复**：
   - 重进考试 → 查询 `status='doing' AND user_id=? AND paper_id=?` → 返回剩余时间 + 已有答案
4. **截屏检测**：
   - `onUserCaptureScreen` → `POST /exam/exam/screenshot-warn { recordId }` → warn_count++
   - warn_count >= max_screenshot_warns → 自动强制交卷 status='cheated'，分数无效

### 判分逻辑

```
score_mode = 'exact' (默认):
  - 单选/判断：答案完全匹配 → 满分, 否则 0
  - 多选：全部选中且无多选 → 满分, 否则 0

score_mode = 'partial' (多选漏选给分):
  - 多选漏选（选了一部分正确选项、无错误选项） → 得分 = 题分 × (选中正确数 / 总正确数)
  - 多选有错误选项 → 0 分

合格 = 得分 >= 试卷合格分数
```

### 已发布试卷编辑限制

- `status='published'` → 仅允许"归档"和"查看"，禁止修改题目组合
- 如需修改已发布试卷 → 克隆新试卷（`version+1`, `status='draft'`），旧卷归档
- `papers/update` API 校验：若 status='published' 则拒绝修改 `question_ids`

### 批量导入容错

`POST /questions/batch-import` 采用部分成功策略：
```json
// 响应格式
{ "success": 85, "failed": 15, "errors": [
  { "row": 3, "reason": "题型字段无效" },
  { "row": 17, "reason": "选项JSON格式错误" }
]}
```
- 逐行校验 → 通过的插入，不通过的回写错误原因
- 不做全部回滚
