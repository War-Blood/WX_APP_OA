## 文档目标

定义工作日报的验收标准。工作日报复用现有日报代码，本期改动为增量，验收聚焦类型放行、统计纳入、标签展示与 Web 管理页。

## 1. 分类 Checklist

### 1.1 功能验收

| # | 验收项 | 角色 | 端 | 通过标准 |
|---|--------|------|-----|---------|
| 1 | 提交工作日报 | employee | 小程序/后端 | 写日报页有「工作日报」Tab，四字段提交成功，daily_reports 出现 report_type='office'、status='approved' |
| 2 | 工作类型可跳过 | employee | 后端 | 提交 office 不传 todayWorkType 不再报「无效的工作类型」 |
| 3 | 历史/详情标签 | employee | 小程序 | 历史与详情显示「工作日报」标签（非原始 'office' 字符串） |
| 4 | 纳入全员当日 | admin | 小程序/后端 | 填了工作日报的人以 status='office' 出现，summary.office 计数；没填且没出差的办公人员不显示、不算缺失 |
| 5 | 纳入明日状态 | admin | 小程序/后端 | 工作日报的明日计划进入明日视图；空类型归「未填写」 |
| 6 | 纳入日历 | admin | 小程序/后端 | 日历该日 submitted 与 total 含工作日报提交者 |
| 7 | Web 管理页 | admin | Webapp | 侧栏出现「工作日报」菜单，列表可筛选、详情弹窗正确显示四字段、可编辑/删除 |
| 8 | 主列表筛选 | admin | Webapp | 日报管理主列表「日志类型」下拉可选「工作日报」，能筛出 office 记录 |
| 9 | 项目进展/人员分布排除 | admin | Webapp | 项目进展、人员分布、个人统计仍不显示工作日报 |

## 2. 质量门 9 项检查

> 阶段 4 implement 代码生成后必须逐项检查，全部通过才允许 git commit。

### 2.1 高优先级（5 项）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 1 | 导航 fail 回退 | 新页面/跳转调用有 fail 回调 |
| 2 | 无静默 catch | 所有 catch 有 Toast/日志 |
| 3 | defineProps 规范 | 使用类型声明 defineProps<Props>() |
| 4 | 无 Mock 数据 | 不残留 mock/假数据 |
| 5 | 无 console 残留 | 生产代码无 console |

### 2.2 中优先级（4 项）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| 6 | z-index 分层 | 按规范 10/100/1000/2000 |

| 8 | API 错误提示 | 统一 showError / ElMessage.error |

## 3. 测试要点

### 3.1 边界条件

| # | 场景 | 预期结果 |
|---|------|---------|
| 1 | 同一用户当天已提交公出日志后再提交工作日报 | 返回 REPORT_ALREADY_SUBMITTED |
| 2 | 工作日报 todayWork 为空提交 | 前端拦截「请输入今日工作内容」 |
| 3 | 明日计划为空的工作日报进明日视图 | 归入「未填写」分组 |
| 4 | 日历某日只有工作日报无出差 | submitted=office 数，total=office 数 |
| 5 | 日期选择非昨天/今天 | 前端 picker 限制，选不到 |

### 3.2 异常处理

| # | 场景 | 预期结果 |
|---|------|---------|
| 1 | 网络断开 | 显示网络异常，可重试 |
| 2 | 接口 500 | 系统异常提示 |
| 3 | 接口 401 | 跳转登录 |
| 4 | 接口 403 | 无权限提示 |
| 5 | 并发提交相同日期工作日报 | 后提交者返回冲突 |

### 3.3 权限场景

| # | 场景 | 预期结果 |
|---|------|---------|
| 1 | employee 访问 Web 工作日报页 | 路由 403 |
| 2 | employee 调用 /report/update | 返回 403 |
| 3 | 未登录访问任意接口 | 返回 401 |
