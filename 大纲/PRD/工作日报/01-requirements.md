## 1. 产品愿景与目标

### 产品一句话简介

工作日报是面向全体员工的日常工作报告——今日工作内容 / 明日计划 / 问题 / 协调四项，复用公出日志填写体系，数据纳入公出统计。

### 核心问题

1. 让不在出差（办公室）的人员也能以简单的四字段表单提报每日工作。
2. 让管理层在公出统计中统一查看全员的提交状态与明日计划。
3. 让 Web 管理端可对工作日报进行查看、编辑、删除与筛选。

### 成功指标

| 指标 | 目标值 | 度量方式 |
|------|--------|---------|
| 工作日报提交成功率 | 100% | 后端 daily_reports 出现 report_type='office' 记录 |
| 统计纳入 | 3/3 视图 | 全员当日/明日状态/日历均可见工作日报 |
| Web 管理可见 | 是 | 工作日报管理页可按 office 类型筛选出记录 |

### OA 系统定位

工作日报是日报模块内的新日志类型（`report_type='office'`），与「公出日志 / 补公出日志」并列，共享 `daily_reports` 表与 `/api/report/*` 接口；统计上纳入公出统计（当日/明日/日历），项目进展/人员分布/个人统计保持排除。与审批无关联（提交即 approved），与考勤共享请假判定。

## 2. 目标用户与场景

### 角色表（RBAC 映射）

| 角色 | RBAC 权限 | 涉及端 | 描述 |
|------|----------|--------|------|
| 普通员工 | employee | 小程序 | 填写每日工作日报、查看历史与详情 |
| 管理员 | admin | 小程序 + Webapp | 在小程序公出统计查看含工作日报的状态；在 Web 工作日报管理页查看/筛选/编辑/删除 |
| 超级管理员 | superadmin | Webapp | 同 admin，系统级兜底 |

### 用户场景

- 场景1：作为员工，我想在写日报页切到「工作日报」Tab 填写今日工作内容，以便在办公室也能提交每日工作报告。（小程序）
- 场景2：作为管理员，我想在小程序公出统计·全员当日看到「工作日报」状态，以便统一掌握全员提交情况。（小程序）
- 场景3：作为管理员，我想在 Web「工作日报」管理页筛选/编辑/删除工作日报，以便纠正异常填报。（Webapp）

### 涉及端

| 端 | 角色 | 说明 |
|----|------|------|
| 小程序 | employee / admin | 填写、历史/详情、公出统计（当日/明日/日历） |
| Webapp | admin / superadmin | 工作日报专门管理页（report/daily） |
| 后端 | — | /api/report/* 与 /api/stats/* 接口 |

### 页面层级

```
L1 工作台 / 功能中心 / 我的
├── L2 写日报（report-edit）
│   └── L3 工作日报 Tab 表单（四字段）
├── L2 日报历史（report-history）
│   └── L3 日报详情（report-detail）
├── L2 公出统计（profile/stats）
│   └── L3 全员当日 / 明日状态 / 日历（含工作日报）
└── L2 Web 工作日报管理页（report/daily）
    └── L3 详情弹窗 / 编辑弹窗 / 删除确认
```

## 3. 功能清单（按优先级）

### P0（必须做 — 核心功能，本期已完成）

| 功能名 | 一句话描述 | 角色 | 端 |
|--------|-----------|------|-----|
| 工作日报填写入口 | 写日报页新增第三个 Tab「工作日报」，隐藏工作类型选择器 | employee | 小程序 |
| 工作日报提交 | 后端放行 report_type='office'，跳过工作类型/项目/作业人员校验，提交即 approved | employee | 后端 |
| 历史/详情标签 | 历史列表与详情页显示「工作日报」类型标签 | employee | 小程序 |
| 纳入全员当日 | 填了工作日报的人以「工作日报」状态计入，只纳入实际填写者 | admin | 小程序/后端 |
| 纳入明日状态 | 工作日报的明日计划进入明日视图（空类型归「未填写」） | admin | 小程序/后端 |
| 纳入日历 | 日历已提交/总人数计入工作日报提交者 | admin | 小程序/后端 |
| Web 工作日报管理页 | admin 查看/筛选/编辑/删除工作日报 | admin | Webapp |

### P1（应该做 — 重要功能）

| 功能名 | 一句话描述 | 角色 | 端 |
|--------|-----------|------|-----|
| 支持补填历史日期 | 工作日报放开日期限制，可补录过去日期（当前与公出一致只填昨天/今天） | employee | 小程序/后端 |

### P2（可以做 — 增强功能）

| 功能名 | 一句话描述 | 角色 | 端 |
|--------|-----------|------|-----|
| 草稿/续写 | 工作日报草稿的本地自动保存与恢复 | employee | 小程序 |
| 统计扩展 | 首页「未填写」统计卡、小程序个人统计纳入工作日报口径 | employee/admin | 小程序/后端 |

> 已明确不列入：工作日报审核流程、隔离演进（work_report_* 独立表）。

## 4. 复用机会

| 组件 | 用途 | 本功能块是否复用 |
|------|------|----------------|
| NavBar | 顶部导航栏 | ☑（写日报页） |
| TabBar | 底部导航 | ☐ |
| List | 通用列表 | ☐（历史页为自定义卡片） |
| Card | 卡片容器 | ☑（表单/详情） |
| Form | 表单容器 | ☐（uni-app 原生 view 表单） |
| Picker | 选择器 | ☑（日期选择） |
| DatePicker | 日期选择 | ☑（填写日期） |
| Upload | 文件/图片上传 | ☐ |

### 数据复用

| 已有数据 | 来源模块 | 复用方式 |
|---------|---------|---------|
| users | 系统基础 | 只读引用（提交人/姓名） |
| daily_reports | 日报模块 | 扩展（新增 report_type='office' 类型值，无 DDL） |
| attendance_leave_requests | 考勤模块 | 只读引用（出差/请假判定） |
| daily_report_workers | 日报模块 | 不写入（工作日报无代填关系） |
