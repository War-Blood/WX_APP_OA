# 结构化需求笔记 — 工作日报

> 日期：2026-08-05
> 说明：基于已实现功能正式化(激活公司日报 office + 纳入公出统计),不推翻现状。

## 1. 产品愿景与目标

- 一句话简介：工作日报是面向全体员工的日常工作报告——今日工作内容 / 明日计划 / 问题 / 协调事项四项,复用公出日志填写体系,数据纳入公出统计。
- 核心问题：让不在出差(办公室)的人员也能以简单的四字段表单提报每日工作,并由管理层在公出统计中统一查看全员的提交状态与明日计划。
- 成功指标：工作日报可正常提交;提交者在公出统计·全员当日以「工作日报」状态可见;明日状态 / 日历计数纳入;Web 管理端可筛选查看。
- OA 系统定位：作为日报模块内的新日志类型(`report_type='office'`),与「公出日志 / 补公出日志」并列。
- 模块关系：与日报模块共享 `daily_reports` 表与 `/api/report/*`;与统计模块共享公出统计视图;与审批模块无关联(提交即 approved,无审核);与考勤模块共享请假判定;不涉及消息 / 公告 / 任务 / WPS。
- 模块类型：**现有模块扩展**(日报模块内的新类型,非全新独立模块)。

## 4. 业务规则与数据实体

### 业务规则

1. 工作日报 = `report_type='office'`;提交即 `status='approved'`、`timeliness='on_time'`,无审核流程。
2. 一人一天一条(UNIQUE `user_id + report_date`);当天已有已提交日报则拒绝重复提交(REPORT_ALREADY_SUBMITTED)。
3. 工作日报**不填工作类型**(后端跳过 todayWorkType 默认与枚举校验)、**不选作业人员**(workers 自动填提交人自己,不写代填表)。
4. 表单字段：今日工作内容必填;明日工作计划 / 遇到的问题 / 需协调事项选填;需协调事项落库 `content` 列。
5. 统计纳入范围：**全员当日 / 明日状态 / 日历**;项目进展、人员分布、区域分布、个人统计、全量 getStats 保持 `report_type != 'office'` 排除。
6. 填报口径：只纳入实际填写者——填了工作日报的人以「工作日报」状态计入;没填且没出差的办公人员不显示、不算缺失。
7. 日历口径：`total` = 当日出差在职人员(且已入场) + 当日填写工作日报的提交者;`submitted` 含工作日报(office 不走 isOnTrip 路径)。
8. 日期限制：只可填昨天/今天(与公出日志一致;请假类型放开限制)。
9. 填工作类型(陆/海/待工/在途/请假)仍强制校验——仅对 office 跳过。

### 数据实体

#### daily_reports(复用现有表,仅新增类型值,无 DDL)

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| id | bigint | 是 | 自增 | 主键 |
| user_id | int | 是 | — | 填报人,UNIQUE(user_id, report_date) |
| report_date | date | 是 | — | 日报日期 |
| report_type | varchar | 是 | office | 日志类型('office' 为工作日报) |
| submitter_name | varchar | 否 | 提交人昵称 | 填写人姓名 |
| today_work | text | 是 | — | 今日工作内容 |
| tomorrow_plan | text | 否 | — | 明日工作计划 |
| issues | text | 否 | — | 遇到的问题 |
| content | text | 否 | — | 需协调事项 |
| today_work_type | varchar | 否 | null | 工作日报为空 |
| workers | varchar | 否 | 提交人自己 | 工作日报无作业人员 |
| project / area / related_party / work_content / machine_model / required_qty / completed_qty | — | 否 | null | 工作日报为空 |
| status | varchar | 是 | approved | 提交即通过 |
| timeliness | enum | 是 | on_time | 及时性 |
| deleted_at | datetime | 否 | null | 软删除 |

### 数据库变更范围

| 类型 | 表名 | 说明 |
|------|------|------|
| 只读复用(无 DDL) | `daily_reports` | 已有 `report_type` 列支持 'office',不需迁移 |

### 实体关系

- `users` 1:N `daily_reports`(填报人)
- 工作日报**不写** `daily_report_workers`(无代填关系),不关联 `wecom_sheet_records`

### 错误码分区

- 复用日报模块错误码号段(REPORT_ALREADY_SUBMITTED / REPORT_SUBSTITUTED / REPORT_DELETE_FORBIDDEN 等),不新分配号段。

## 5. UI/UX 关键词及关键页面

### 风格关键词

简洁、移动优先、分段 Tab、卡片式、状态色区分

### 设计令牌确认

- 主色：#2B6DE8 / 成功：#22C55E / 警告：#F59E0B / 危险：#EF4444
- 小程序 rpx(750)、卡片圆角 16rpx、Flex-First
- Web 端 Element Plus 表格 + 弹窗

### 关键页面

#### 写日报页(report-edit,L2/L3)

- 主要元素：顶部三段日志类型 Tab、日期选择、四字段表单(今日工作内容必填 / 明日计划 / 问题 / 协调)、提交按钮
- 交互行为：切到「工作日报」Tab 时清空工作类型与作业人员、隐藏今日状态条;提交成功返回
- 数据来源：`reportApi.submit` / `reportApi.getDraft`

#### 公出统计(stats.vue,L2)

- 主要元素：全员当日(今日/明日双模式)、日历热力图;「工作日报」状态组(绿色 tag)
- 交互行为：按状态分组展示;明日按工作类型分组,空类型归「未填写」;点击卡片进详情
- 数据来源：`reportApi.getDailyStatus` / `getTomorrowStatus` / `getDailyCounts`

#### Web 工作日报管理页(report/daily,L2)

- 主要元素：筛选工具栏(关键词/状态/日期)、表格(时间/填写人/今日工作/明日计划/问题/协调/状态)、详情弹窗、编辑/删除
- 交互行为：行点击看详情;编辑弹窗改四字段;删除带 10 秒撤销
- 数据来源：`getReportList({ reportType: 'office' })` / `getReportDetail` / `updateReport` / `deleteReport`

## 7. API 需求清单

### 端点列表

| 端点 | 方法 | 说明 | 角色 |
|------|------|------|------|
| `/api/report/submit` | POST | 提交工作日报(reportType='office') | employee |
| `/api/report/list` | POST | 列表,新增 `reportType` 筛选(工作日报页用 office) | 登录 / admin |
| `/api/report/detail` | POST | 日报详情(含工作日报四字段) | 登录 |
| `/api/report/update` | POST | 编辑工作日报 | admin+ |
| `/api/report/delete` / `/restore` | POST | 删除 / 恢复 | 登录 / admin |
| `/api/report/daily-status` | POST | 全员当日(含 office 状态) | admin |
| `/api/report/tomorrow-status` | POST | 明日状态(含工作日报明日计划) | admin |
| `/api/stats/daily-counts` | POST | 日历已提交/总人数(含工作日报) | 登录 |

### 约定

- 全部 POST + JSON body
- 统一响应：`{ code, message, data }`
- 分页：`{ page, pageSize }` → `{ total, list }`
- 认证：Bearer Token(JWT);角色中间件 `requireRole('admin','superadmin')` 用于管理端
- 错误码：复用日报模块错误码,不新分配
