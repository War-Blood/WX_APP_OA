## 文档目标

定义组织架构管理模块的完整需求规格，含愿景、用户、场景、功能清单。

## 1. 产品愿景与目标

- **一句话简介**：为 OA 系统搭建部门分级管理和员工组织归属体系
- **核心问题**：现有角色体系仅控制操作权限，缺少组织架构层级
- **成功指标**：superadmin 可增删改部门 | admin 可查看完整组织树 | 员工归属到具体部门
- **OA 系统定位**：基础设施模块，为审批流/考勤/日报提供部门维度数据基础

## 2. 目标用户与场景

| 角色 | RBAC | 端 | 描述 |
|------|------|-----|------|
| superadmin | superadmin | Web 后台 | 新增/编辑/删除部门、调整层级、级联清空、分配员工部门+职位 |
| admin | admin | Web 后台 | 查看完整组织树（仅 GET，不可操作） |
| employee | employee | — | 不涉及（不查看组织树） |

### 核心场景

- **场景1**：superadmin 管理组织架构。在 Web 后台左侧看 5 级部门树，右键新增子部门/编辑/删除，级联清空子部门和员工关联。
- **场景2**：admin 查看组织架构。在 Web 后台查看完整部门树及每个部门下的人员列表，不可编辑。
- **场景3**：superadmin 分配员工部门。在用户列表选中员工 → 选择所属部门 + 职位（枚举），保存后同步更新 departments 表。

## 3. 功能清单

| 优先级 | 功能 | 描述 |
|--------|------|------|
| P0 | 部门树展示 | 左侧 el-tree，5 级展开收起，点击选中 |
| P0 | 部门 CRUD | 新增子部门、编辑名称/上级、删除 |
| P0 | 员工分配部门 | 在用户列表选人 → 选部门 → 选职位（枚举） |
| P0 | **级联清空删除** | 删父部门 → 子部门全软删 → 员工 department_id 置 NULL |
| P0 | **权限修复** | POST/PUT/DELETE → superAuth；GET → adminAuth |
| P1 | 层级拖拽调整 | 拖拽移动节点改变 parent_id |
| P1 | 批量分配部门 | 勾选多个员工 → 批量设部门 |
| P2 | 部门人员统计 | 每个节点显示人数 |
