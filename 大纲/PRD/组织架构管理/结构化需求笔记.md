# 结构化需求笔记 — 组织架构管理

> 日期：2026-07-10
> 访谈模式：混合访谈（7 维度覆盖）

## 1. 产品愿景与目标

- **一句话简介**：为 OA 系统搭建部门分级管理和员工组织归属体系
- **核心问题**：现有角色体系（employee/admin/superadmin）仅控制操作权限，缺少组织架构层级
- **成功指标**：admin 可查看完整组织树；superadmin 可增删改部门；员工归属到具体部门
- **OA 系统定位**：基础设施模块，为后续审批流/考勤/日报的部门维度提供数据基础
- **模块关系**：全新独立模块，但代码已作为 core 模块的一部分存在于 backend/src/core/ 中

## 2. 用户与场景

| 角色 | RBAC | 端 | 核心场景 |
|------|------|-----|---------|
| superadmin | superadmin | Web 后台 | 新增/编辑/删除部门、调整层级、分配员工部门 |
| admin | admin | Web 后台 | 查看组织树（仅查看，不操作） |
| employee | employee | 不涉及 | 不查看组织树 |

### 核心场景

1. **superadmin 管理组织架构**：在 Web 后台左侧看部门树，右键新增子部门/编辑/删除，级联清空
2. **admin 查看组织架构**：在 Web 后台查看完整部门树及每个部门下的人员
3. **superadmin 分配员工部门**：在用户列表选中员工 → 选择部门 + 职位

### 页面层级
- Web 后台：L2 功能列表（管理后台 → 组织架构管理）

## 4. 业务规则与数据实体

### 核心业务规则
- 部门 5 级：员工 → 组长 → 部长 → 经理 → 总经理
- 删除部门：级联软删除所有子部门 + 该部门及子部门下所有员工 department_id 置 NULL
- 上级部门不能设为自己
- 职位为固定枚举：员工/组长/部长/经理/总经理

### 数据实体
- `departments` 表（已存在）— 部门信息（id/name/parent_id/sort_order/status）
- `users` 表（已存在）— department_id（外键）+ position（枚举字符串）

### 数据库变更范围
- **不新建表**：departments 表已存在
- **不改表结构**：users.department_id/users.position 已存在
- **仅修改代码**：admin.service.js deleteDepartment + admin.routes.js 权限

## 5. UI/UX 关键词及关键页面

- **整体风格**：复用 OA Web 后台现有布局（DefaultLayout + AppSidebar + AppHeader）
- **设计令牌**：主色 #2B6DE8
- **关键页面**：组织架构管理页 — 左树（el-tree）右详情（部门信息 + 人员列表）

## 7. API 需求

- GET `/admin/departments` — 部门树（已有）→ admin+
- POST `/admin/departments` — 新增部门（已有）→ 改 superAuth
- PUT `/admin/departments/:id` — 编辑部门（已有）→ 改 superAuth
- DELETE `/admin/departments/:id` — 删除部门（已有）→ 改 superAuth + 改级联清空
