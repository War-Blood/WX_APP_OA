## 1. 结论摘要

1. 推荐 **学之思(mindskip/xzs)** 作为三端考试系统的 Schema 与功能参考——Web 端 + 微信小程序、Java + Vue 前后端分离、MySQL/PostgreSQL 双版本,社区最成熟。
2. 推荐 **ExamOnline(DavidAlphaFox)** 作为题型与刷题交互参考——8 大题型(单选/多选/填空/判断/阅读等)、多媒体题库、刷题/错题本/收藏/排行榜/激活码/会员体系。
3. 推荐 **kesixin 系列** 作为"三端互通"架构参考——PC/H5/小程序三端数据互通、uniapp 小程序、Java/PHP 后端,覆盖练习(顺序/随机/专项/题型/高频错题)/背题/模拟考试/错题/收藏/排行/签到/积分。
4. **三端分工共识**:小程序 = 答题端(刷题/考试/练习),Web = 管理端(题库/试卷/成绩/统计),后端 = 统一 API。**现有答题模块三端分工与此一致** ✓
5. 现有答题模块三端代码已实现但处于"**暂缓验收**"状态;调研主要用于:确认数据模型合理性、锁定 6 个遗留缺口为 P0、错题本等参考功能列入 P1/P2。

## 4. 数据模型对比

参考项目核心业务链:**题目 — 试卷 — 答题明细 — 成绩/错题**

| 环节 | 参考项目典型表 | 现有 `exam_*` 表 | 对比 |
|---|---|---|---|
| 题库 | `question`(题型/题干/选项/答案/解析/难度/分值) | `exam_questions` ✓ | 一致,含 options JSON |
| 试卷 | `paper` + `paper_question` 关联表(每题分值/排序) | `exam_papers`(question_ids JSON) | 用 JSON 而非关联表(题目量小可接受) |
| 答题 | `exam_answers`(user/paper/question/答案/对错/得分) | `exam_records`(answers JSON + **question_snapshot** 快照) | 用 JSON;快照冻结设计优于参考 |
| 成绩 | `exam_results`(总分/对错数/时长/状态) | `exam_records` ✓ | 一致 |
| 错题 | `e_wrong_question` 或从答题记录 `is_correct=false` 推导 | **无** | 缺口:可从 `exam_records.answers` + 快照推导,成本低 |
| 分类 | `subject`(学科/等级) | `exam_categories`(分类树,表已建) | **无 CRUD** 缺口 |

**结论**:现有 4 表设计与参考项目同构,且快照/版本字段更优;不需要为对齐参考而改表。错题本 P1 可从现有数据推导,不新增表。

## 6. 对现有模块的建议与差距

### P0(推进阶段实施,已列入 08 验收)
1. 题库分类树管理 — `exam_categories` 表已建,补 API + Web 分类 UI
2. 超时扫描定时任务 — 后端 cron 扫 doing 超时 → timeout
3. 试卷克隆/版本管理 — 修改已发布试卷自动克隆 + version 递增
4. 小程序结果页逐题详情 — 交卷传 details,渲染对错 + 解析
5. 结果页从记录进入传分 — 修复 0 分显示
6. Web `any` 清理 — 补 TS 类型

### P1/P2(参考功能,后续迭代)
- **错题本**(P1,推荐):从 `exam_records.answers` 中 `correct=false` 推导,复习入口
- 背题模式(P2):参考 kesixin 智慧考题宝
- 排行榜/积分(P2):参考 ExamOnline / kesixin(适合趣味竞赛场景)
- 多媒体题库(P2):图片/语音/视频题干(参考 ExamOnline)

### 不建议本期做
- 填空/简答主观题:需关键词/人工判分,复杂度高,与"三种客观题"基调不符
- 试卷-题目关联表重构:现有 JSON 方案在题目量级下够用

## 10. 合并决策（2026-08-07，PRD v2.0）

> 调研角色：产品决策。目标：确定答题模块最终技术路线 —— **整个答题系统并入现有 OA 单项目**。

### 10.1 决策结论

| 项 | 决策 |
|----|------|
| 形态 | **并入 OA 单项目**（非独立小程序跳转、非 H5 内嵌、非两个项目） |
| 技术 | 按 kesixin/dati 功能/数据模型，在 OA 自有栈重建：Express+MySQL 后端 / uni-app 小程序 / Vue3 Web 后台 |
| 数据 | 落 OA MySQL，**不依赖 Bmob 云后端** |
| 处置 | **全部删除**旧自研答题模块（含 exam_papers 试卷模型、发放/范围/防作弊/催考） |
| 管理端 | OA Web 后台**单独「答题管理」模块**（分类/题库/记录/统计/设置） |
| 用户 | 复用 OA `users` + JWT，**不做 dati 的独立注册审核** |

### 10.2 仓库审计（针对"uni-app"说法重新核实）

| 仓库 | 内容 | 结论 |
|------|------|------|
| [kesixin/dati](https://github.com/kesixin/dati) | 原生微信小程序（app.json/app.wxss/pages .wxml/.wxss/.js + `utils/Bmob-1.6.7.min.js`），作者 AppID `wx8860ba4f74c3aaff`、Bmob key 硬编码 | **非 uni-app** |
| [kesixin/QuestionWechatApp](https://github.com/kesixin/QuestionWechatApp) | 同为原生微信小程序 + Bmob SDK | **非 uni-app** |
| kesixin/kesixin | 仅 README 说明页 | 无源码 |

> **结论**：开源仓库中**不存在** dati 的 uni-app 小程序源码；「小程序端使用 uniapp 开发」对应的是收费产品智汇考题。因此小程序答题 UI 需在 OA 的 uni-app 工程内**按 dati 流程重建**（dati 仅作设计/交互参照）。

### 10.3 dati 功能纳入/舍弃决策

| 纳入 | 说明 |
|------|------|
| 分类（含二级 questionMenu） | 抽题/练习/考试按分类组织，显示题量与建议时长 |
| 题库（questions 单/多/判断） | options/answer/analysis 结构一致，批量导入 |
| 练习刷题（learn） | 顺序/随机/专项/题型 + **背题模式** |
| 模拟考试 / 正式考试 | 随机抽题 + 限时 + 答题卡 + 交卷判分 |
| 成绩页（examResult 逐题） | 对错 + 解析 |
| 错题本 / 收藏 | dati 本地 storage → OA 服务端持久化 |
| 答题记录 / 排行榜 | 按分类按人最高分 |
| 答题设置（setting） | use_learn / check_user |

| 舍弃 | 理由 |
|------|------|
| Bmob 云后端 + Bmob `_User` 注册审核 | 数据落 OA、身份用 OA 用户 |
| 签到 / 积分 / 激活码 / 虚拟支付 / 激励广告 | dati 商业化功能，OA 内部场景不需要 |
| 资讯文章 | 与 OA 定位不符 |
| formId 订阅消息 | 微信能力受限，未纳入 |

### 10.4 旧 v1.2 模型废弃说明

| 旧功能 | 处置 |
|--------|------|
| 考卷/试卷（exam_papers + 手动选题/随机抽题规则/分组/乱序） | **删除**；合并后按 dati「分类→随机抽题」模型 |
| 考卷发放（范围 all/department/user/role + 发布通知 + 催考） | **删除**；按分类开放 |
| 成绩展示掩码（result_visibility manual） | **删除**；交卷即见成绩 |
| 防作弊（截屏警告/cheated） | **删除** |
| 试卷克隆 / 版本管理 | **删除** |

### 10.5 参考价值留存

合并重建仍保留以下参考价值：
- **答题卡网格 / 背题模式 / 错题本 / 排行榜** UX 沿用 dati 设计（见 05-ui-ux）。
- **快照冻结**（question_snapshot）为 OA 旧实现优点，合并后继续使用。
- **多选部分分**（score_mode='partial'）保留。
