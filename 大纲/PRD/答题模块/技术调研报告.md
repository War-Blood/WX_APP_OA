# 技术调研报告：答题模块三端设计

> 调研日期：2026-08-05
> 调研角色：代码架构师 / 开源情报分析师
> 调研目标：为 OA"答题模块"(原"考试模块",含刷题练习 + 正式考试)寻找可参考的开源三端方案,对比现有实现,支撑 PRD 更新与推进阶段补齐遗留缺口。

---

## 1. 结论摘要

1. 推荐 **学之思(mindskip/xzs)** 作为三端考试系统的 Schema 与功能参考——Web 端 + 微信小程序、Java + Vue 前后端分离、MySQL/PostgreSQL 双版本,社区最成熟。
2. 推荐 **ExamOnline(DavidAlphaFox)** 作为题型与刷题交互参考——8 大题型(单选/多选/填空/判断/阅读等)、多媒体题库、刷题/错题本/收藏/排行榜/激活码/会员体系。
3. 推荐 **kesixin 系列** 作为"三端互通"架构参考——PC/H5/小程序三端数据互通、uniapp 小程序、Java/PHP 后端,覆盖练习(顺序/随机/专项/题型/高频错题)/背题/模拟考试/错题/收藏/排行/签到/积分。
4. **三端分工共识**:小程序 = 答题端(刷题/考试/练习),Web = 管理端(题库/试卷/成绩/统计),后端 = 统一 API。**现有答题模块三端分工与此一致** ✓
5. 现有答题模块三端代码已实现但处于"**暂缓验收**"状态;调研主要用于:确认数据模型合理性、锁定 6 个遗留缺口为 P0、错题本等参考功能列入 P1/P2。

## 4. 数据模型对比

参考项目核心业务链:**题目 — 试卷 — 答题明细 — 成绩/错题**

| 环节 | 参考项目典型表 | 现有 `exam_*` 表 | 对比 |
|---|---|---|---|
| 题库 | `question`(题型/题干/选项/答案/解析/难度/分值) | `exam_questions` ✓ | 一致,含 options JSON |
| 试卷 | `paper` + `paper_question` 关联表(每题分值/排序) | `exam_papers`(question_ids JSON) | 用 JSON 而非关联表(题目量小可接受) |
| 答题 | `exam_answers`(user/paper/question/答案/对错/得分) | `exam_records`(answers JSON + **question_snapshot** 快照) | 用 JSON;快照冻结设计优于参考 |
| 成绩 | `exam_results`(总分/对错数/时长/状态) | `exam_records` ✓ | 一致 |
| 错题 | `e_wrong_question` 或从答题记录 `is_correct=false` 推导 | **无** | 缺口:可从 `exam_records.answers` + 快照推导,成本低 |
| 分类 | `subject`(学科/等级) | `exam_categories`(分类树,表已建) | **无 CRUD** 缺口 |

**结论**:现有 4 表设计与参考项目同构,且快照/版本字段更优;不需要为对齐参考而改表。错题本 P1 可从现有数据推导,不新增表。

## 5. 三端分工共识

| 端 | 职责 | 参考项目对应 |
|---|---|---|

| Web 后台 | 管理端:题库 / 试卷 / 成绩统计 / 分类管理(待加) | 学之思 Web 管理 |

## 6. 对现有模块的建议与差距

### P0(推进阶段实施,已列入 08 验收)
1. 题库分类树管理 — `exam_categories` 表已建,补 API + Web 分类 UI
2. 超时扫描定时任务 — 后端 cron 扫 doing 超时 → timeout
3. 试卷克隆/版本管理 — 修改已发布试卷自动克隆 + version 递增
4. 小程序结果页逐题详情 — 交卷传 details,渲染对错 + 解析
5. 结果页从记录进入传分 — 修复 0 分显示
6. Web `any` 清理 — 补 TS 类型

### P1/P2(参考功能,后续迭代)
- **错题本**(P1,推荐):从 `exam_records.answers` 中 `correct=false` 推导,复习入口
- 背题模式(P2):参考 kesixin 智慧考题宝
- 排行榜/积分(P2):参考 ExamOnline / kesixin(适合趣味竞赛场景)
- 多媒体题库(P2):图片/语音/视频题干(参考 ExamOnline)

### 不建议本期做
- 填空/简答主观题:需关键词/人工判分,复杂度高,与"三种客观题"基调不符
- 试卷-题目关联表重构:现有 JSON 方案在题目量级下够用

## 7. 问卷星考试系统调研（2026-08-06，PRD v1.2 借鉴）

> 调研角色：产品分析师。目标：为考卷设置 / 题目设置 / 考卷发放 三块寻找成熟产品参照,输出借鉴项与用户确认。

### 7.1 功能全景

| 能力域 | 问卷星能力 |
|--------|-----------|
| 考卷设置 | 题库随机抽题(按题目/按分页 A-B 卷/按题型)、开始/结束时间、最长作答时间、每日定时开考、防作弊(切屏次数限制、答题无操作强制交卷、密码验证、IP/设备限制)、练习模式、断点续答、提交前预览 |
| 题目设置 | 单选/多选/判断/填空(多答案+模糊匹配)/简答、题目分值、答案解析、选项随机排列、题目分组/分页、题库随机设置 |
| 考卷发放 | 二维码/链接、企微/钉钉/飞书组织架构精准选人、一键催答、倒计时提醒、成绩单自定义、成绩报表筛选导出、错题集、排名 |
| 成绩呈现 | 自动阅卷、交卷即时得分(可设置是否显示)、逐题作答情况、名次、正确率分析 |

### 7.2 与 OA 现有实现对比及借鉴决策（用户已确认）

| 借鉴项 | 问卷星做法 | OA 落地设计 | 确认 |
|--------|-----------|------------|:--:|
| 随机抽题 | 题库随机设置:按题型/分类抽指定数量 | `exam_papers.draw_rules` + 开始考试时随机抽题冻结快照 | ✅ 本期 |
| 题目/选项乱序 | 选项随机排列 | `shuffle_questions`/`shuffle_options` 试卷级开关 + 单题开关 | ✅ 本期 |
| 成绩展示控制 | 提交后是否显示成绩单 | `result_visibility` immediate/manual + `result_released` | ✅ 本期 |
| 无操作强制交卷 | 超过指定秒数无操作强制交卷 | 不做(与截屏警告重复,本次用户未选) | — |
| 每日定时开考 | 每日指定时间开始/结束 | 不做(低频,需求未现) | — |
| 试卷内分组 | 分页分组 | `exam_papers.sections` + 答题端分区渲染 | ✅ 本期 |
| 难度等级 | 无显式难度标签 | 不做(用户未选) | — |
| 发布通知/催考 | 一键催答/倒计时提醒 | publish 站内信 + `papers/remind`(复用 messages) | ✅ 本期 |
| 成绩导出 | 报表筛选导出 | `records/export` → CSV(BOM) | ✅ 本期 |
| 发放范围 | 组织架构选人 | scope_type 扩为 all/department/user/role | ✅ 本期 |

### 7.3 小结

问卷星强在**防作弊随机化**与**发放/回收运营**两大块;OA 已具备限时窗口/断线恢复/截屏防作弊,本次按用户选择补齐:随机抽题、乱序、成绩展示控制、分组、选项乱序开关、通知催考、导出、范围扩展。未选的无操作强制交卷 / 难度等级 / 每日定时开考不纳入本期。

## 8. kesixin/dati 答题小程序调研（2026-08-06，答题端 UX 参考）

> 仓库：https://github.com/kesixin/dati — 开源的答题/考试/刷题小程序（uniapp 小程序端,96 个 page,无后端/建表,管理端另用 vue.js + SpringBoot/PHP 版）。

### 8.1 页面结构（答题端）

| 页面 | 用途 | 对 OA 的参考 |
|------|------|------------|
| index | 主界面:分类 + 题目搜索 | 练习入口检索 |
| category | 分类浏览 | 分类树(已有) |
| dati | 答题:答题模式/背题模式 Tab 切换 | 背题模式(P2,强化) |
| exam / examResult | 考试列表 / 考试结果 | 考试+结果页(已有) |
| moniq | 模拟考试独立入口 | 练习(已有) |
| wrong / errorStar | 错题本 + 错题重练 | 错题本(P1,强化重练入口) |
| record / rank | 记录 / 排行榜 | 记录(已有) / 排行(P2) |
| learn / questions | 学习 / 题目搜索 | — |

### 8.2 答题 UX 要点

- **答题模式/背题模式** Tab 切换：答题=作答判分;背题=逐题直接显示答案供记忆(强化背题模式 P2)。
- **答题卡网格**：底部方格一题一格,题号跳转 + 已答/对错状态——与 OA 05-ui-ux「答题卡网格签名」一致,互为印证。
- **实时统计**：答题中实时显示已答数/正确数/错误数——OA 练习已实现。
- **随机抽题**：`getRandomArrayElements` 从题库随机抽题——印证随机抽题本期价值。
- **Storage 缓存**：考试数据缓存本地,断线可续——OA 已用快照+断线恢复。

### 8.3 借鉴结论

kesixin/dati 是**纯答题端**设计参考,与 OA 小程序答题端对齐:答题卡网格跳转(已在 05-ui-ux)、背题模式/错题本/排行(强化 P1/P2 描述)。本期不新增页面,不做实现。
