## 文档目标

明确本功能块"做什么、给谁用、优先级"。

## 1. 角色与权限

| 角色 | 能力 |
|------|------|
| admin | 管理脚本/群机器人/查看执行日志；测试发送（受限流） |
| superadmin | 拥有 admin 全部能力；**失败告警站内消息的唯一收件角色** |
| employee | 不可访问本模块（无入口、无 API 权限） |

## 2. 功能需求清单

| ID | 需求 | 说明 | 优先级 |
|----|------|------|--------|
| REQ-01 | 脚本管理 | 创建/编辑/启停推送脚本；定义触发时间（每天固定时间或 cron 表达式） | P0 |
| REQ-02 | 群机器人管理 | 配置可用的企微群机器人（引用服务端 env 凭证，不落库不展示） | P0 |
| REQ-03 | 发送条件配置 | 按预定义数据源字段比较判定（AND/OR），不满足则不发送 | P0 |
| REQ-04 | 人员 @ 配置 | 不@ / @所有人 / 按角色 / 按指定人员；text 用手机号、markdown 用企微 userid | P0 |
| REQ-05 | 消息模板 | 自定义内容，支持内置变量与数据源字段变量替换 | P0 |
| REQ-06 | Webhook 集成 | 对接企微群机器人 webhook：加签鉴权、固定请求格式、指数退避重试 | P0 |
| REQ-07 | 日志与监控 | 记录每次执行：条件判定、渲染结果、@ 目标、发送状态、错误信息、耗时 | P0 |
| REQ-08 | 失败告警 | 发送失败站内消息告警（仅 superadmin）；连续失败自动停用脚本 | P1 |
| REQ-09 | 限流与熔断 | 每脚本每日发送上限；测试发送限流；连续失败熔断 | P1 |
| REQ-10 | 手动测试 | 管理员可 dryRun 预览（条件判定 + 渲染结果）或真实发送 | P1 |
| REQ-11 | 凭证安全 | 对齐 WPS：webhook key/secret 仅存 `.env`，前端/API/日志零接触 | P0 |
| REQ-12 | 审计 | 群机器人/脚本的增删改与测试发送写入操作日志（operation_logs） | P2 |

## 3. 用户故事

- 作为管理员，我希望配置"每天 08:30 检查昨日日报缺失人数，>0 时向生产群发提醒并 @ 对应人员"，这样无需人工盯数据。
- 作为管理员，我希望消息内容里能自动带上日期、缺失人数、人员姓名，而不必每天手改。
- 作为超级管理员，我希望发送失败时能收到站内消息，且机器人连续失败后自动停用，避免反复打扰群里成员。
- 作为管理员，我担心 webhook 地址泄露后被乱发消息——要求凭证不出服务端、消息必须带合法签名，即使 URL 泄露也无法投递垃圾消息。

## 4. 非功能需求

| 项 | 要求 |
|----|------|
| 时区 | 调度按脚本 timezone（默认 Asia/Shanghai） |
| 可靠性 | 同分钟重复触发只发一次（Redis 锁 + 幂等键）；PM2 多实例安全 |
| 性能 | 单脚本执行 < 10s（不含重试）；不阻塞主进程（异步执行） |
| 安全 | 凭证零暴露；加签防伪造；出站固定 URL；参数化 SQL |
| 兼容 | 遵循 `大纲/设计规范/01-api-design.md`；错误码 2700-2799 分区 |

## 5. 反模式（刻意避免）

| 反模式 | 说明 | 对策 |
|--------|------|------|
| 任意 SQL 条件 | 管理员配置自由 SQL 判定条件 | 预定义数据源白名单 |
| 凭证落库/落前端 | webhook key 明文存 DB 或前端可读 | 服务端 env 独占（对齐 WPS） |
| 自定义 webhook URL | 脚本配置任意 URL 作为发送目标 | 后端固定拼接企微域名 |
| 无上限循环重试 | 失败后无限重试冲击企微与群 | 重试次数上限 + 熔断 + 每日上限 |
| 条件为空时默认发送 | 空条件误判为"恒真" | 空条件默认不发送，保存时校验 |
