# 考勤模块 (Attendance) — 测试用例

> 版本：v1.0 | 覆盖范围：后端 19 API + 小程序 7 页面 + Web 3 视图 | 基于代码审查设计

---

## 一、后端 API 测试用例

### 1.1 排班管理 (8 端点)

---

#### TC-SCH-001: schedule/list — 管理员查询排班（正常）

| 项目 | 内容 |
|------|------|
| **前置条件** | 已认证 admin/superadmin Token |
| **输入** | `{ startDate: "2026-07-01", endDate: "2026-07-31" }` |
| **预期** | code=0, 返回分页数据 { list, total, page, pageSize, totalPages } |
| **验证点** | list 每项含 userId, userName, departmentName, scheduleDate, status, note |

#### TC-SCH-002: schedule/list — 按部门筛选

| 项目 | 内容 |
|------|------|
| **输入** | `{ startDate, endDate, departmentId: 1 }` |
| **预期** | 仅返回该部门人员的排班 |

#### TC-SCH-003: schedule/list — 按用户筛选

| 项目 | 内容 |
|------|------|
| **输入** | `{ startDate, endDate, userId: 5 }` |
| **预期** | 仅返回该用户的排班 |

#### TC-SCH-004: schedule/list — 参数缺失

| 项目 | 内容 |
|------|------|
| **输入** | `{ startDate: "2026-07-01" }` （缺少 endDate） |
| **预期** | code≠0, message="起止日期不能为空" |

#### TC-SCH-005: schedule/list — 普通员工 403

| 项目 | 内容 |
|------|------|
| **前置条件** | employee 角色 Token |
| **预期** | 403 Forbidden |

#### TC-SCH-006: schedule/upsert — 正常新增排班

| 项目 | 内容 |
|------|------|
| **前置条件** | admin Token |
| **输入** | `{ userId: 5, scheduleDate: "2026-07-15", status: "rest", note: "调休" }` |
| **预期** | code=0, data: { id, updated: true } |

#### TC-SCH-007: schedule/upsert — 更新已存在排班

| 项目 | 内容 |
|------|------|
| **输入** | 同上，但 userId+scheduleDate 已存在 |
| **预期** | code=0, 覆盖原记录 |

#### TC-SCH-008: schedule/upsert — 参数缺失

| 项目 | 内容 |
|------|------|
| **输入** | `{ userId: 5 }` （缺 scheduleDate/status） |
| **预期** | "userId/scheduleDate/status 必填" |

#### TC-SCH-009: schedule/batch — 批量排班（仅工作日）

| 项目 | 内容 |
|------|------|
| **输入** | `{ userIds: [5,6], startDate: "2026-07-01", endDate: "2026-07-31", status: "work", weekdaysOnly: true }` |
| **预期** | code=0, 仅周一至周五生成排班 |

#### TC-SCH-010: schedule/batch — 参数不完整

| 项目 | 内容 |
|------|------|
| **输入** | `{ userIds: [], startDate: "2026-07-01" }` |
| **预期** | "参数不完整" |

#### TC-SCH-011: schedule/delete — 正常删除

| 项目 | 内容 |
|------|------|
| **输入** | `{ id: 123 }` |
| **预期** | code=0, data: { deleted: true } |

#### TC-SCH-012: schedule/delete — 删除不存在的记录

| 项目 | 内容 |
|------|------|
| **输入** | `{ id: 99999 }` |
| **预期** | code=2802, "排班记录不存在" |

#### TC-SCH-013: schedule/my-schedule — 员工查自己排班（正常）

| 项目 | 内容 |
|------|------|
| **前置条件** | employee Token |
| **输入** | `{ startDate: "2026-07-01", endDate: "2026-07-31" }` |
| **预期** | code=0, 返回该用户排班数组 [{ id, userId, scheduleDate, status, note }] |

#### TC-SCH-014: schedule/my-schedule — 无排班数据

| 项目 | 内容 |
|------|------|
| **输入** | 查询未排班月份 |
| **预期** | code=0, data: [] |

#### TC-SCH-015: schedule/rules — 获取规则列表

| 项目 | 内容 |
|------|------|
| **前置条件** | admin Token |
| **预期** | code=0, 返回规则数组，默认规则排在首位 |

#### TC-SCH-016: schedule/rules/save — 新增规则

| 项目 | 内容 |
|------|------|
| **输入** | `{ name: "标准5天", weekConfig: {1:"work",2:"work",3:"work",4:"work",5:"work",6:"rest",7:"rest"} }` |
| **预期** | code=0, data: { id, created: true } |

#### TC-SCH-017: schedule/rules/save — 设默认规则

| 项目 | 内容 |
|------|------|
| **输入** | `{ id: 1, name, weekConfig, isDefault: true }` |
| **预期** | 其他规则的 isDefault 被设为 0 |

#### TC-SCH-018: schedule/rules/apply — 应用规则到全员

| 项目 | 内容 |
|------|------|
| **输入** | `{ ruleId: 1, startDate: "2026-07-01", endDate: "2026-07-31" }` |
| **预期** | code=0, 返回 { inserted, skipped, total }，每个在职用户每日一条排班 |

### 1.2 请假管理 (6 端点)

---

#### TC-LEAVE-001: leave/apply — 正常请假

| 项目 | 内容 |
|------|------|
| **前置条件** | employee Token |
| **输入** | `{ leaveSubtype: "sick", startDate: "2026-07-10", endDate: "2026-07-12", reason: "身体不适" }` |
| **预期** | code=0, 返回 { requestId, days: 3, status: "active" }；排班逐日覆盖为 leave |

#### TC-LEAVE-002: leave/apply — 请假半天（边界）

| 项目 | 内容 |
|------|------|
| **输入** | `{ leaveSubtype: "personal", startDate: "2026-07-10", endDate: "2026-07-10", reason: "半天" }` |
| **预期** | code=0, days: 1 |

#### TC-LEAVE-003: leave/apply — 未选子类型

| 项目 | 内容 |
|------|------|
| **输入** | `{ startDate, endDate, reason }` （无 leaveSubtype） |
| **预期** | code=2810, "请假必须指定子类型" |

#### TC-LEAVE-004: leave/apply — 结束日期早于开始日期

| 项目 | 内容 |
|------|------|
| **输入** | `{ leaveSubtype: "sick", startDate: "2026-07-10", endDate: "2026-07-05" }` |
| **预期** | code=2806, "结束日期不能早于起始日期" |

#### TC-LEAVE-005: leave/apply — 请假跨月（边界）

| 项目 | 内容 |
|------|------|
| **输入** | `{ leaveSubtype: "annual", startDate: "2026-06-28", endDate: "2026-07-03" }` |
| **预期** | days: 6, 排班覆盖两个月的日期 |

#### TC-LEAVE-006: leave/my-list — 查询请假列表

| 项目 | 内容 |
|------|------|
| **输入** | `{ requestType: "leave", page: 1 }` |
| **预期** | code=0, 分页返回请假记录 |

#### TC-LEAVE-007: leave/my-list — 筛选出差类型

| 项目 | 内容 |
|------|------|
| **输入** | `{ requestType: "biz_trip", status: "in_progress" }` |
| **预期** | 仅返回进行中的出差 |

#### TC-LEAVE-008: leave/detail — 查看请假详情

| 项目 | 内容 |
|------|------|
| **输入** | `{ requestId: 1 }` |
| **预期** | code=0, 含 applicantName, departmentName, missingDates（出差时） |

#### TC-LEAVE-009: leave/detail — 不存在的申请单

| 项目 | 内容 |
|------|------|
| **输入** | `{ requestId: 99999 }` |
| **预期** | code=2802, "申请单不存在" |

#### TC-LEAVE-010: leave/cancel — 撤销请假

| 项目 | 内容 |
|------|------|
| **前置条件** | 存在 active 状态的请假 |
| **输入** | `{ requestId: 1 }` |
| **预期** | code=0, 状态变更为 cancelled，排班恢复为 work |

#### TC-LEAVE-011: leave/cancel — 重复撤销

| 项目 | 内容 |
|------|------|
| **前置条件** | 请假已撤销 |
| **预期** | code=2805, "申请已撤销不可重复撤销" |

#### TC-LEAVE-012: leave/cancel — 撤销出差

| 项目 | 内容 |
|------|------|
| **前置条件** | 出差记录 |
| **预期** | code=2813, "出差不可撤销，请使用结束打卡" |

#### TC-LEAVE-013: leave/update — 修改请假

| 项目 | 内容 |
|------|------|
| **前置条件** | active 请假 |
| **输入** | `{ requestId: 1, leaveSubtype: "annual", startDate: "2026-07-11", endDate: "2026-07-14", reason: "更新" }` |
| **预期** | code=0, 旧记录 cancelled，新记录 active，排班重新覆盖 |

#### TC-LEAVE-014: leave/update — 修改非本人请假

| 项目 | 内容 |
|------|------|
| **预期** | code=1001, "无权操作" |

#### TC-LEAVE-015: leave/delete — 管理员删除已撤销记录

| 项目 | 内容 |
|------|------|
| **前置条件** | admin Token，请假已 cancelled |
| **输入** | `{ requestId: 1 }` |
| **预期** | code=0, 记录删除，排班恢复 |

#### TC-LEAVE-016: leave/delete — 删除 active 记录（异常）

| 项目 | 内容 |
|------|------|
| **前置条件** | 请假状态 active |
| **预期** | 拒绝删除，"仅已撤销/已结束的记录可删除" |

### 1.4 考勤汇总 (3 端点)

---

#### TC-SUM-001: summary/list — 管理员查汇总

| 项目 | 内容 |
|------|------|
| **前置条件** | admin Token |
| **输入** | `{ startDate: "2026-07-01", endDate: "2026-07-31" }` |
| **预期** | code=0, 每人 { workDays, restDays, bizTripDays, leaveDays, missingDays } |

#### TC-SUM-002: summary/list — 优先级验证

| 项目 | 内容 |
|------|------|
| **场景** | 某天既有公出日志(在途)又有排班(work) |
| **预期** | 该天计为 bizTripDays（公出日志优先级 > 排班） |

#### TC-SUM-003: summary/list — 未提交检测

| 项目 | 内容 |
|------|------|
| **场景** | 用户处于出差中(in_progress)，某天无公出日志也无请假 |
| **预期** | 该天 missingDays+1 |

#### TC-SUM-004: summary/export — 导出 Excel

| 项目 | 内容 |
|------|------|
| **前置条件** | admin Token |
| **预期** | Content-Type: application/vnd.openxmlformats...，双 Sheet |

#### TC-SUM-005: summary/my-summary — 员工查个人汇总

| 项目 | 内容 |
|------|------|
| **前置条件** | employee Token |
| **输入** | `{ startDate: "2026-07-01", endDate: "2026-07-31" }` |
| **预期** | code=0, 返回 { workDays, restDays, bizTripDays, leaveDays, missingDays, dailyList } |

#### TC-SUM-006: summary/my-summary — dailyList 含每日状态

| 项目 | 内容 |
|------|------|
| **预期** | dailyList 中每天有 { date, status, note }，公出日志日 note 含 work_content |

## 二、小程序页面验收用例

### 2.1 我的排班 (my-schedule)

| 编号 | 用例 | 预期 |

### 2.2 请假申请 (leave-apply)

| 编号 | 用例 | 预期 |
|:--:|------|------|
| MP-101 | 选择「年假」→ 提交 | leaveSubtype = "annual" |
| MP-102 | 选择「事假」→ 提交 | leaveSubtype = "personal" (非 "sick"，见 BUG-01) |
| MP-103 | 选择「病假」→ 提交 | leaveSubtype = "sick" (非 "personal"，见 BUG-01) |
| MP-104 | 开始日期 > 结束日期 | 前端拦截，提示错误 |
| MP-105 | 不填原因提交 | 前端拦截，提示"请输入请假原因" |
| MP-106 | 从详情页修改入口进入 | URL 参数正确填充 editId/type/start/end/reason |
