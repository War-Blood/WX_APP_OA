# 访谈 7 维度详细参考

> 本文档是 `arch-foundation-probe` 的详细参考。
> SKILL.md 只含交互规则与维度概要，每个维度的完整问题清单、OA 适配说明、复用组件清单在此文档中。

## 维度 1 — 产品愿景与目标

### 问题清单

- 产品一句话简介？
- 核心解决的问题是什么？
- 成功指标是什么？
- 该模块在 OA 系统中的定位？
- 与现有模块的关系？
- 是全新独立模块还是对现有模块的扩展？

### OA 系统定位

该模块在 OA 系统中的定位需明确与以下现有模块的关系：

- 日报模块
- 审批模块
- 考勤模块
- 合规模块
- WPS 模块
- 项目模块
- 消息模块
- 公告模块
- 任务模块

### 模块关系判断

- **全新独立模块**：与现有模块无直接数据依赖，独立运作
- **现有模块扩展**：在现有模块基础上新增功能，可能共享数据表或服务
- **跨模块协同**：需要读取或写入其他模块的数据，需定义接口边界

## 维度 2 — 目标用户与场景

### 问题清单

- 用户角色有哪些？
- 每个角色的核心场景是什么？（≥3 个）
- 各角色的权限差异？

### 角色映射到 RBAC

OA 系统三级角色体系：

| 角色 | 权限范围 | 典型场景 |
|------|---------|---------|
| `employee` | 个人数据读写 + 公共数据只读 | 提交日报、查看公告、打卡 |
| `admin` | 部门/全员数据管理 | 审批、统计、配置规则 |
| `superadmin` | 系统级配置 | 用户管理、角色分配、系统设置 |

### 涉及端

- **miniapp**：移动端，适合轻量操作、即时通知、现场采集
- **webapp**：PC 端，适合批量操作、数据分析、复杂表单
- **both**：两端都需要，需明确各端的功能差异

### 页面层级

| 层级 | 说明 | 示例 |
|------|------|------|
| L1 | Tab 主页 | 首页、工作台、我的 |
| L2 | 功能列表 | 日报列表、审批列表 |
| L3 | 详情编辑 | 日报详情、审批详情 |
| L4 | 弹窗浮层 | 确认弹窗、筛选面板 |

## 维度 4 — 业务规则与数据实体

### 问题清单

- 核心业务规则有哪些？（用自然语言描述）
- 数据实体及字段是什么？（字段级详细程度）
- 数据库变更范围：新建表？扩展已有表？只读引用旧表？
- 实体间关系是什么？（一对一/一对多/多对多）
- 错误码分区号段是多少？

### 业务规则

用自然语言描述每条规则，包含：

- 触发条件
- 执行动作
- 约束限制
- 异常处理

### 数据实体

每个实体需明确：

- 实体名称
- 字段列表（名称 + 类型 + 是否必填 + 默认值 + 说明）
- 主键策略（自增 ID / UUID / 业务主键）
- 软删除字段（`is_deleted` / `deleted_at`）

### 数据库变更范围

| 类型 | 说明 | 风险 |
|------|------|------|
| 新建表 | 全新实体，无影响 | 低 |
| 扩展已有表 | 新增字段，需迁移脚本 | 中（需兼容旧数据） |
| 只读引用旧表 | 仅 SELECT，不修改结构 | 低 |

### 实体关系

- 一对一（1:1）
- 一对多（1:N）
- 多对多（M:N，需中间表）

### 错误码分区

每个模块分配独立错误码号段，避免冲突。格式：`<模块号><错误序号>`，如 `40xxx` 为考勤模块。

## 维度 7 — API 需求

### 问题清单

- 主要端点需求有哪些？（资源 + 动作）
- 认证方式？
- 角色中间件需求？
- 错误码约定？

### API 约定

- **方法**：全部 POST + JSON body（不使用 GET/PUT/DELETE）
- **统一响应格式**：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

- **分页**：

请求：
```json
{
  "page": 1,
  "pageSize": 20
}
```

响应：
```json
{
  "code": 0,
  "data": {
    "total": 100,
    "list": []
  }
}
```

### 认证

- 方式：Bearer Token（JWT）
- Header：`Authorization: Bearer <token>`
- 角色中间件：`requireRole('admin')` / `requireRole('superadmin')`

### 错误码约定

| code | 含义 |
|------|------|
| 0 | 成功 |
| 401 | 未认证 |
| 403 | 无权限 |
| 4xx | 业务错误 |
| 5xx | 系统错误 |
