# 每日工作日报生成

## 触发时机

- 每次代码改动 + 提交 + 部署完成后
- 用户说"生成日志"、"写工作日志"、"写日报"、"记录今天的工作"
- 会话结束前（如果期间有代码改动）

## 输出路径

```
需求/任务日志/YYYY-MM-DD.md
```

如果该日文件已存在，追加新内容（不覆盖已有记录，对应工作日报「一人一天一条」，见 PRD 规则 2）。

## 日报模板

严格按照以下四字段格式输出（对齐 `大纲/PRD/工作日报/00-index.md` 口径）：

```markdown
# 工作日报 — YYYY-MM-DD

---

## 今日工作内容

（必填，≤100 字。一句到两句高概括当日核心工作，可点出功能模块；不逐条罗列 commit/文件）

- 完成答题模块四项修复（练习记录清理/Web 选题/部门树/按钮验证）

## 明日工作计划

（选填。从待办 / 下一步任务推导，可执行）

- [ ] 计划项 1

## 遇到的问题

（选填。当日阻塞、异常、未解决 bug，写清现状）

- 问题 1：现状描述

## 需协调事项

（选填。需他人配合 / 领导确认 / 跨部门协调；含「待上传发布 / 待人工验收 / 待产品确认」类）

- 协调 1：事项描述

---

## 开发补充（提报公司日报时删除本段）

### 完成明细
- 事项 1（涉及模块，`xxxxxxx`）｜ 事项 2 …

### 部署状态
| 层 | 状态 | 备注 |
|------|:--:|------|
| 后端 | ✅/❌ | PM2 重启 / 未部署 |
| 小程序 | ✅/❌ | 已构建 / 未构建 |
| Webapp | ✅/❌ | 已构建 / 未构建 |

### 验证结果
- 验证项 1 ✅/❌

### 待处理
- [ ] 待办项 1

---

*自动生成*
```

完整模板参考：`references/template.md`

## 工作流程

1. **收集信息**：回顾当前会话的 git log（`git log --oneline -10`）与改动文件，找出本次会话的新提交与涉及模块
2. **提炼今日工作内容**：按提交/功能归组，用 ≤100 字高概括当日核心工作（commit/文件明细归入开发补充·完成明细）
3. **推导明日工作计划**：从待办、后续步骤、未完成事项推导可执行计划
4. **提炼遇到的问题**：当日阻塞、异常、未解决 bug
5. **提炼需协调事项**：需他人配合、上传发布、人工验收、产品确认的事项
6. **记录开发补充**：完成明细、部署状态、验证结果、剩余待处理
7. **写入文件**：写入 `需求/任务日志/YYYY-MM-DD.md`，如已有则追加

## 注意事项

- 今日工作内容**必填且 ≤100 字**，高概括可扫描；commit/文件明细全部归入开发补充·完成明细
- 明日计划 / 问题 / 协调选填，字数参考 1000/500/500（PRD 05-ui-ux）
- 一人一天一条：当日文件已存在则追加，不新建重复文件
- 日期仅昨日/今日（补填历史日期暂不支持，为 PRD P1 待办）
- commit hash 取短格式（7 位，如 `be4b230`）
- 事项描述使用中文，简洁明了
- 如果某层未改动，标注"无需"而非"未部署"
- 模板参考文件：`references/template.md`；口径对齐：`大纲/PRD/工作日报/00-index.md`
