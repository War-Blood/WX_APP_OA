# 数据库备份与恢复

> 目标：服务器被攻击/被清盘后，数据可**完整修复**。
> 机制：**每日加密备份 + 异地副本**（加密保机密性，异地保可用性）。

## 一、备份在哪

| 位置 | 内容 | 保留 |
|------|------|------|
| 服务器 `/var/www/wx-app-oa/backups/db/` | 每日加密 dump（`.sql.gz.gpg`） | 30 天 |
| 异地本机 `D:\SQL\db\` | 从服务器拉取的加密副本（每日） | 长期（只增不减） |

> 加密文件用 **gpg 公钥**加密，**私钥仅存异地本机**（`C:\Users\yf\.gnupg`）→ 即使服务器被攻破，攻击者也只能删除、无法读取数据。

## 二、自动化

- **服务器每日备份**（cron root）：`30 2 * * * /var/www/wx-app-oa/scripts/backup-db.sh >> /var/log/oa-backup.log 2>&1`
- **异地拉取**（Windows 计划任务 `OA-DB-Backup-Pull`）：每日 03:30 运行 `D:\Tools\Git\usr\bin\bash.exe -lc "bash /d/Projects/OA/backend/scripts/pull-backups.sh"`，把服务器备份同步到 `D:\SQL\db\`

## 三、恢复步骤

### 正常恢复（误操作/小范围）
1. 选一个服务器或本地的加密备份文件
2. 在**异地本机**执行：
   ```bash
   bash /d/Projects/OA/backend/scripts/restore-db.sh <D:\SQL\db\YYYYMMDD_HHMMSS.sql.gz.gpg> [wx_app_oa]
   ```
3. 脚本会：本地解密 → 先对生产做一次加密快照 → 经 ssh 管道导入生产库（明文不落生产盘）

### 灾难恢复（服务器被清盘/需重建）
1. 重新部署后端代码 + 还原 `.env`（含 `OA_DB_*`）到新机器
2. 用**本地 `D:\SQL\db\` 最新的加密备份**恢复：
   ```bash
   bash /d/Projects/OA/backend/scripts/restore-db.sh <D:\SQL\db\最新备份.sql.gz.gpg> wx_app_oa
   ```
   （restore 脚本中的 `wx-app-server` 改为新机器 SSH 别名即可）
3. 如需**秒级 PITR**：结合服务器 binlog（保留 30 天）`mysqlbinlog` 增量回放（binlog 在服务器本地，仅当服务器未清盘时可用）

### 恢复到临时库演练（验证备份可用）
```bash
# 异地解密到明文
gpg -d 备份.gpg | gunzip > /tmp/drill.sql
# 服务器 sudo 建临时库并导入（应用账号无建库权限，用 sudo mysql）
scp /tmp/drill.sql wx-app-server:/tmp/
ssh wx-app-server "sudo mysql -e 'CREATE DATABASE IF NOT EXISTS oa_restore_drill;' && sudo mysql oa_restore_drill < /tmp/drill.sql"
# 比对关键表行数后 DROP 临时库
```

## 四、密钥管理（重要）

- **gpg 密钥对**：`OA-DB-Backup <backup@oa.local>`（RSA-3072，仅加密用途）
  - 公钥已导入服务器（只能加密，不能解密）
  - 私钥在本机 `C:\Users\yf\.gnupg`（唯一能解密的密钥）
- ⚠️ **请为私钥再做一份离线备份**（如导出 `.asc` 存到安全的移动介质/密码管理器），否则密钥丢失将无法解密任何备份
- 吊销证书：`C:\Users\yf\.gnupg\openpgp-revocs.d\*.rev`

## 六、边界与增强

- **损失窗口**：每日一备，最多丢失最近备份后 ~24 小时增量；如需更小窗口改小时级备份
- **binlog 异地同步**：当前 binlog 只在服务器本地，被清盘即失；后续可增配 binlog 异地归档以支持秒级 PITR
- **恢复演练频率**：建议每季度执行一次"恢复到临时库"演练
