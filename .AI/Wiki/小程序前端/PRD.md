## 1. 产品概述

### 1.1 产品背景

中小微企业在数字化转型过程中面临以下核心痛点：

- **办公碎片化**：审批、日报、任务、公告分散在不同工具（微信、钉钉、邮件、Excel），信息割裂严重
- **管理透明度低**：日报靠微信群接龙，审批靠口头传达，管理者无法实时掌握团队工作进度
- **部署成本高**：传统OA系统部署复杂、费用高昂，不适合中小微企业的轻量化需求
- **移动办公刚需**：一线员工（施工、运维、销售等）以移动端为主要工作设备，缺乏适配的移动办公工具
- **数据孤岛**：项目进度、人员考勤、资产状态等数据无法打通，决策缺乏数据支撑

### 1.2 产品定位

**智慧办公助手**是一款基于微信小程序的轻量化OA办公系统，定位为：

- **零部署、即开即用**：依托微信生态，无需下载安装，扫码即可使用
- **核心办公场景全覆盖**：聚焦审批流程、日报管理、任务协作、项目管理、资产台账、公告通知六大核心场景
- **模块化、可扩展**：采用前后端分离架构，模块间低耦合，支持按需启用功能模块
- **角色化视角**：提供员工端与管理端两套操作界面，权限分明，操作简洁
- **数据驱动管理**：通过日报数据、项目进度、审批统计等为管理者提供决策依据

### 1.3 目标用户

| 用户角色                    | 职责描述                                                  | 核心需求                                         | 用户规模预期 |
| --------------------------- | --------------------------------------------------------- | ------------------------------------------------ | ------------ |
| **普通员工**          | 一线执行人员，需每日汇报工作、发起审批、查看任务          | 日报填写与提交、审批发起、任务查看、个人数据查询 | 80%          |
| **部门主管/项目经理** | 中层管理者，需审核日报、审批申请、跟踪项目进度            | 日报审核、审批处理、任务分配、项目进度查看       | 15%          |
| **企业管理员**        | 高层管理者/系统管理员，需用户管理、权限控制、全局数据查看 | 用户权限管理、全局审批、数据统计、系统配置       | 5%           |

### 1.4 核心价值主张

| 价值维度           | 具体体现                                               |
| ------------------ | ------------------------------------------------------ |
| **效率提升** | 日报填写模板化，审批流程自动化，减少沟通成本 60%+      |
| **管理透明** | 日报提交率、审批时效、项目进度数据实时可视化           |
| **成本节约** | 零部署成本，无需硬件投入，基于微信现有生态             |
| **决策支持** | 日报数据分析、审批统计、项目进度报表为管理决策提供依据 |
| **体验统一** | 一个入口完成所有办公操作，告别多工具切换               |

### 1.5 产品范围

#### 1.5.1 核心功能（P0 — 必须实现）

- 用户登录与身份认证（微信一键登录 + 开发调试模式）
- 工作台首页：待办统计聚合、快捷功能入口、待办事项、最近动态时间线
- 功能中心：全功能网格入口，按角色分组展示（办公协作/信息中心/系统设置）
- 个人中心：用户信息展示、数据统计、设置列表、退出登录
- 审批流程：多Tab审批中心（待审批/我发起的/已处理）、审批类型筛选、审批卡片列表
- 底部导航系统：3个主Tab（首页/功能/我的）统一导航

#### 1.5.2 重要功能（P1 — 建议实现）

- 日报管理：日报编辑/详情/历史/驳回重提
- 审核管理：管理员审核列表/详情、通过/驳回操作
- 消息通知：消息中心、分类展示、未读标记、详情跳转
- 任务管理：任务看板、任务分配、进度跟踪
- 项目管理：项目列表、项目详情、项目成员管理
- 资产管理：资产台账、领用/归还、资产盘点
- 公告系统：企业/部门两级公告、发布管理
- 用户管理：管理员用户列表、角色权限、账号状态管理

#### 1.5.3 增值功能（P2 — 可选实现）

- 高级审批：并行审批、加签/转签、条件审批
- 数据报表：甘特图、工时统计、效率分析
- 考勤管理：签到打卡、请假/加班申请
- 文档管理：在线文档、文件共享

## 2. 功能需求

### 2.1 用户认证与权限模块

#### 2.1.1 功能描述

提供安全、便捷的用户认证体系，支持微信生态一键登录和开发调试模式，基于角色实现细粒度的权限控制。

#### 2.1.2 功能列表

| 功能编号 | 功能名称     | 功能描述                                                                      | 优先级 | 用户角色 | 实现状态  |
| -------- | ------------ | ----------------------------------------------------------------------------- | ------ | -------- | --------- |
| AUTH-01  | 微信一键登录 | 通过微信授权获取用户信息（昵称、头像），调用后端 /api/auth/login 接口完成认证 | P0     | 全部     | ✅ 已实现 |
| AUTH-02  | 开发调试登录 | 跳过微信授权直接进入首页，注入调试 Token 和用户信息，便于开发测试             | P0     | 开发     | ✅ 已实现 |
| AUTH-03  | 协议确认     | 登录前需勾选同意《用户协议》和《隐私政策》，未勾选时拦截并提示                | P0     | 全部     | ✅ 已实现 |
| AUTH-04  | Token 管理   | 基于 JWT 的登录态管理，Token 持久化到 localStorage，支持退出登录清除          | P0     | 全部     | ✅ 已实现 |
| AUTH-05  | 角色权限控制 | 基于 RBAC 模型，定义员工/管理员角色，权限矩阵控制功能可见性                   | P0     | 全部     | ⏳ 待完善 |
| AUTH-06  | 用户管理     | 管理员可查看用户列表、设置管理员权限、禁用/启用账号                           | P1     | 管理员   | ⏳ 待创建 |
| AUTH-07  | 页面路由守卫 | 根据登录态自动拦截未授权页面访问，无 Token 时跳转登录页                       | P0     | 系统     | ⏳ 待完善 |

#### 2.1.3 认证流程（当前实现）

```
[用户打开小程序]
    ↓
[登录页（pages/login/index）]
    ↓
┌─────────────────────────────────────┐
│ 方式一：微信一键登录                  │
│ [点击"微信一键登录"]                  │
│   → 校验协议是否勾选                   │
│   → 调起 wx.login 获取 code          │
│   → POST /api/auth/login 认证        │
│   → 缓存 Token + 用户信息            │
│   → redirectTo 首页                   │
├─────────────────────────────────────┤
│ 方式二：开发调试登录                  │
│ [点击"跳过登录，进入首页 ›"]         │
│   → 注入调试 Token                   │
│   → 缓存模拟用户信息（角色/部门）    │
│   → redirectTo 首页                   │
└─────────────────────────────────────┘
```

## 3. 非功能需求

### 3.1 性能需求

| 指标         | 目标值   | 说明                           |
| ------------ | -------- | ------------------------------ |
| 页面首次加载 | ≤ 2秒   | 从打开小程序到首页渲染完成     |
| 页面切换     | ≤ 1秒   | Tab 切换或页面跳转响应时间     |
| API 响应时间 | ≤ 500ms | 90% 的 API 请求在 500ms 内返回 |
| 列表分页加载 | ≤ 1.5秒 | 每页 20 条数据加载时间         |
| 日报提交     | ≤ 2秒   | 提交日报到显示成功结果         |
| 首包体积     | ≤ 2MB   | 微信小程序代码包大小限制       |
| 运行时内存   | ≤ 200MB | 正常使用场景                   |

### 3.2 安全需求

| 需求编号 | 安全需求     | 说明                                         | 优先级 |
| -------- | ------------ | -------------------------------------------- | ------ |
| SEC-01   | HTTPS 加密   | 所有 API 通信必须使用 TLS 1.2+ 加密          | P0     |
| SEC-02   | Token 认证   | 使用 JWT Bearer Token，持久化到 localStorage | P0     |
| SEC-03   | 敏感数据脱敏 | 手机号、身份证等敏感信息脱敏处理             | P0     |
| SEC-04   | 输入校验     | 前端 + 后端双重输入校验，防止 XSS/SQL 注入   | P0     |
| SEC-05   | 权限校验     | 后端每个接口进行角色权限校验                 | P0     |
| SEC-06   | 数据隔离     | 员工只能查看自己相关数据                     | P0     |
| SEC-07   | 操作日志     | 关键操作记录日志                             | P1     |
