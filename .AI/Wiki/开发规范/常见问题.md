# 开发规范常见问题

## 代码规范

### Q: ESLint 报错如何自动修复
**A**: 运行 `npm run lint:fix` 自动修复可修复的问题。运行 `npm run format` 格式化代码。

### Q: 命名规范不一致
**A**: 严格按以下标准：
- 文件名: kebab-case（如 `user-list.vue`）
- 变量/函数: camelCase（如 `getUserById`）
- 类: PascalCase（如 `UserService`）
- 常量: UPPER_SNAKE_CASE（如 `MAX_COUNT`）

## Git 工作流

### Q: Commit 信息写错了
**A**: 如果尚未推送，运行：
```bash
git commit --amend -m "正确的提交信息"
```

### Q: 分支命名不规范
**A**: 分支命名格式：
- 功能: `feature/xxx`
- 修复: `fix/xxx`
- 紧急: `hotfix/xxx`
- 发布: `release/v*.*.*`

---

## Code Review

### Q: Review 退回了如何操作
**A**: 按 Review 意见修改代码后重新提交：
```bash
git add .
git commit -m "fix: 按 review 意见修改"
git push origin feature/xxx
```

### Q: Review 检查清单在哪里
**A**: 见 [Code Review 清单](Code%20Review%20清单.md) 或 `.trae/rules/review-checklist.md`。
