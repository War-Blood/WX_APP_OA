# 错误码与错误处理规范

> 本文件定义后端 API 的错误码清单、分类和处理模式。所有后端开发与测试必须遵循。

---

## 统一响应格式

所有 API 响应均返回 HTTP 200，通过 `code` 字段区分业务状态：

```json
{ "code": 0, "message": "success", "data": { ... } }
```

> **注意**: 项目错误处理中间件将所有异常统一转换为 HTTP 200 响应，客户端应检查 `code` 字段而非 HTTP 状态码。

---

## 错误码清单

| code | 常量名 | 含义 | 处理方式 |
|------|--------|------|---------|
| 0 | `SUCCESS` | 请求成功 | 正常读取 data |
| 401 | `AUTH` | 认证失败（未登录/token 过期/WX 登录失败） | 跳转登录页 |
| 403 | `FORBIDDEN` | 权限不足 | 提示"无权操作" |
| 1001 | `VALIDATION` | 参数校验失败 | 提示 message 中的具体校验错误 |
| 1002 | `NOT_FOUND` | 资源不存在 | 提示"数据不存在" |
| 2001 | `BUSINESS` | 业务逻辑错误 | 提示 message 内容 |
| 2002 | `APPROVAL_ALREADY_PROCESSED` | 审批已处理（重复操作） | 静默刷新列表 |
| 2003 | `REPORT_ALREADY_REVIEWED` | 日报已审核（重复操作） | 静默刷新详情 |

---

## 错误处理分层

| 层级 | 职责 | 禁止 |
|------|------|------|
| **Controller** | 参数校验（Joi）、抛出 `ValidationError` | 不处理业务异常 |
| **Service** | 抛出 `BusinessError` / `NotFoundError` | 不直接返回响应 |
| **Middleware** (`errorHandler.js`) | 统一捕获所有异常并转换为 JSON | 不做业务判断 |
| **前端** (`request.js`) | 检查 `code !== 0` → `showToast` / 跳转登录 | 不解析 HTTP 状态码 |

---

## 错误类定义

```
AppError (基类)
├── AuthError       → code: 401
├── ForbiddenError  → code: 403
├── ValidationError → code: 1001
├── NotFoundError   → code: 1002
└── BusinessError   → code: 2001 / 2002 / 2003
```

---

## 使用示例

```javascript
// Controller 层：参数校验失败
if (!account) throw new ValidationError('请输入账号');

// Service 层：资源不存在
const user = await db.query('SELECT * FROM users WHERE id = ?', [id]);
if (!user) throw new NotFoundError('用户不存在');

// Service 层：业务逻辑错误
if (record.status !== 'pending') throw new BusinessError('该记录不是待处理状态');

// Service 层：重复操作冲突
if (approval.status !== 'pending') throw new BusinessError('审批已处理，请勿重复操作');
if (report.review_status === 'reviewed') throw new BusinessError('日报已审核，请勿重复操作');
```

> **注意**: 当前 `errorHandler.js` 将所有 `BusinessError` 统一映射为 `code: 2001`。如需在前端区分 code 2002/2003，需扩展 `BusinessError` 类支持自定义 code 参数。错误码 2002/2003 已在 `constants.js` 中声明，可供后续实现使用。
