# Code Review 检查清单 — Review Checklist

## 适用范围

- **适用对象**: 所有 AI 工具（Qoder / Cursor / Claude Code / Trae）
- **触发场景**: 代码审查、PR 审查、代码质量评估
- **预期产出**: 审查报告（通过/有条件通过/退回）

---

## 一、功能正确性

### 业务逻辑
- [ ] 代码实现与需求文档一致
- [ ] 边界条件已处理（空值、越界、异常输入）
- [ ] 状态机转换正确（如审批流程：pending → approved/rejected）
- [ ] 事务管理正确（失败时回滚）

### API 接口
- [ ] 路径/方法/参数与 API 文档一致
- [ ] 响应格式符合 `{ code, message, data }` 规范
- [ ] 错误码定义合理且文档化
- [ ] 分页参数（page/pageSize）和响应（total/list）规范

---

## 二、代码质量

### 结构与设计
- [ ] 符合分层架构（routes → controllers → services → db）
- [ ] 无跨层调用（如 routes 直接操作数据库）
- [ ] 函数/方法职责单一
- [ ] 无重复代码块（DRY 原则）

### 命名
- [ ] 变量/函数/类命名表达意图
- [ ] 无缩写歧义（`usr` → `user`，`btn` → `button`）
- [ ] 布尔变量以 `is`/`has`/`should` 开头

### 复杂度
- [ ] 函数的圈复杂度 ≤ 10
- [ ] 单函数行数 ≤ 100
- [ ] 无深层嵌套（最多 4 层缩进）
- [ ] 无过度设计（不需要的抽象、泛化）

---

## 三、安全性

- [ ] SQL 查询使用参数化查询，禁止字符串拼接
- [ ] 用户输入经过校验（Joi/express-validator）
- [ ] JWT token 验证在受保护路由上正确实施
- [ ] 敏感数据（密码/token）不记录日志
- [ ] 无硬编码密钥/密码/凭证
- [ ] API 权限校验 100% 覆盖

---

## 四、性能

- [ ] 数据库查询有合适的索引
- [ ] N+1 查询已优化
- [ ] 热点数据有缓存策略
- [ ] 无同步阻塞操作（如需异步处理的任务）
- [ ] 文件上传/下载不分块处理时注意内存使用

---

## 五、可维护性

- [ ] 公共函数有 JSDoc 注释
- [ ] 复杂逻辑有行注释说明
- [ ] 无注释掉的死代码
- [ ] 无 `console.log` / `debugger` / `TODO`（除非有意保留）
- [ ] 错误信息对用户友好且包含足够的调试信息

---

## 六、测试

- [ ] 新功能有对应的单元测试
- [ ] Bug 修复有对应的回归测试
- [ ] 核心业务逻辑测试覆盖率 ≥ 60%
- [ ] 测试用例包含正常路径和异常路径
- [ ] 测试命名清晰: `should_xxx_when_xxx`

---

## 审查结论

| 结论 | 条件 |
|------|------|
| ✅ 通过 | 所有必检项通过，建议项 ≤ 2 项未通过 |
| ⚠️ 有条件通过 | 仅建议项未通过，且已记录待处理 |
| ❌ 退回 | 存在功能/安全/质量必检项未通过 |
