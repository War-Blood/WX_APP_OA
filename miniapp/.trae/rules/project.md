## 技术栈（已确认）

- **框架**: uni-app（Vue 3 + Vite）— 从原生小程序全量迁移
- **语言**: JavaScript (ES6+) + Vue 3 Composition API
- **样式**: SCSS + CSS 变量（高效蓝 #2B6DE8 主题）
- **UI 组件库**: uni-ui（DCloud 官方）
- **状态管理**: Pinia（替代 app.globalData）
- **TabBar**: uni-app 内置 tabBar
- **后端**: 自定义服务端 API（本地 VM Mock → https://warblood.online）

> 详细技术规范请参阅：[技术规范.md](./技术规范.md)

## 强制开发规范

### 1. 上下文加载
- **每次任务开始前必须加载 project.md**
- 确保了解项目背景、技术栈和当前进度

### 2. 意图确认
- **每次接到任务后，必须仔细分析用户意图**
- 遇到不理解或认为意图模糊时，**必须反问用户确认**
- 确认好意图后再进行开发，不得擅自猜测

### 3. Agent 协同
- **执行任务时选取合适的 Agent 调用**
- 如果能同时协同多个 Agent，则**协同调用多个 Agent** 提升任务效率

### 4. Git 管理
- **每次修改都需要维护 git 仓库**
- 提交代码修改记录到本地仓库
- **用户未主动要求，不得擅自提交到远程仓库**

### 5. 后端 API 规范（核心原则）

> **重要**: 这是一个纯粹的前端项目，所有业务数据通过后端 API 获取

- 后端 API 端点遵循 PRD 第 2.10.3 节定义的接口规范
- 遇到后端调用问题时，**严格按照后端 API 文档进行调用**
- 如果发现后端 API 有问题，**直接返回问题原因在后端**
- **不得**强行改变前端业务逻辑来适配后端

### 6. README 维护
- 项目根目录下维护 `README.md` 说明该目录下项目内容的情况

### 7. PRD 对齐
- 所有新增功能必须在 PRD 中有明确定义
- PRD 中规定的功能模块必须完整实现
- 不得在项目中引入 PRD 未提及的功能模块
